Изменения внесены поверх `e5de88f` в текущей ветке. Тесты, сборка и инференс агентом **не запускались по указанию пользователя**. Это непроверенный кандидат, не новый baseline. Полные измерения M сохранены пользователем в [отчёте, §13](BENCHMARK-REPORT.md); они не заменяются новыми наборами.

## Что изменено

- Опоры AHC — отдельные эмбеддинги установленных реплик, максимум 6 с чистой речи внутри реплики. При наличии коротких реплик сохраняется прежний допуск 1 с; короткие локальные окна не создают дополнительные опоры. Если извлечение опоры не удалось, допускается одно самое длинное успешное окно этой реплики.
- Окна 1,8 с назначаются по фиксированным центроидам опор. Они уточняют покрытие; уже назначенные окна не передвигают центроиды для последующих назначений. Опора убирается из покрытия там, где доступны локальные измерения, чтобы не удваивать длительность.
- Финальная диаризация получает подготовленный канал. Канал без усиления остаётся исходным благодаря существующему bridge. ASR, проверка профилей и дедупликация сохраняют прежний исходный вход. Сам ASR-фикс M не менялся.
- Cannot-link соблюдается также при fixed-k и конфликтующем максимуме: искусственные запрещённые слияния больше не применяются для достижения заданного k. Если требования несовместимы, результат может содержать больше заданного максимума; `ev=cluster.constraint_limit` показывает requested/retained k.
- `ev=diar.clusters` содержит отсортированные размеры групп и уникальную длительность речи на стадиях `ahc`, `coverage`, `tiny_merge`, `validated`, `assignment`, `smoothing`, `final`. `ev=diar.fixed_k` явно показывает отключённые защиты; `ev=diar.coverage_reject` — удалённые группы. `ev=diar.embedding_frontend` показывает использование подготовленного канала. Логи не содержат текстов, имён или векторов.
- Основной EN/RU 2spk-набор с разными предложениями и согласованными противоположными metadata gender подготовляется отдельно. Нормализация RMS 0,1 включается явным флагом; normal/quiet используют общий headroom. Старые stress6, исторические записи, их исходные уровни и gate сохраняются. Для 3–4 разных дикторов с разными предложениями FLEURS не даёт здесь достаточных ID; такие гарантии не выдумываются.
- Пример `embedding_separability` считает диагностические cross/within cosine на исходном и подготовленном сигнале штатным экстрактором. Он не исключает файлы и не выбирает пороги. Описание и команды — в [README](../../tools/diar_eval/README.md).

Пороги AHC/coverage, silhouette, сопоставления профилей и сглаживания не подстраивались. Новая модель, AS-Norm, ослабление порога разделения и безусловное включение mono `reassign_short_replies` не добавлены: они требуют самостоятельной проверки, а не следуют из представленных измерений. Масштаб PCM в fbank сохранён как численная совместимость с reference при малом уровне, а не заявлен как решение похожих голосов.

## Короткий измерительный прогон перед 450 файлами

Сначала пересобрать новый бинарник, сохранить отдельную неизменяемую копию и SHA-256. Старые `m-round3`, `matrix-m` и baseline не перезаписывать. На новом кандидате сначала повторить исходные четыре встречи, их quiet-пару, прежний stress6 и Vox5; использовать прежние манифесты и настройки. Dev-opt прогон нужен для новых стадийных логов: release отключает логирование. Не сравнивать его скорость с release.

Отдельно подготовить основной набор:

```bash
"$PY" tools/diar_eval/prepare_main_meetings.py "$ROOT"
```

Манифесты `$ROOT/diar-main-meetings/{normal,quiet}.json` проверяются отдельно через `run_batch.py`. SHA доказательства отбора записан в манифест. Этот более простой набор не заменяет прежние неудачные результаты и не делает их проходящими.

При проверке важно увидеть, сформировались ли разные группы **опор реплик** после AHC, затем какой шаг меняет их размеры. Рост confusion на Vox не компенсируется улучшением основной синтетики. Если короткий прогон оправдывает продолжение, повторить Crowd300 → матрицу36 → Farfield100 → FLEURS50 на той же копии бинарника с парным WER-сравнением.

Для причинного разбора M разделять последующие изменения: опоры AHC, вход эмбеддингов и защиты кластеризации. Совместный прогон этой правки оценивает результат кандидата, но не устанавливает вклад каждого компонента. Абляции frontend/fbank/coverage M из приложенного разбора остаются самостоятельными экспериментами; автоматического прогона или новых runtime-переключателей для них здесь нет.
