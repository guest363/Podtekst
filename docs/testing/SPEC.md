# Спецификация стенда качества Podtekst

Статус: действующая спецификация.
Владелец: инженер по машинному обучению и аудио.
Область: настольные сборки Linux, macOS, Windows. Мобильная версия и локальные итоги встреч в это техническое задание не входят.

Быстрый вход: [README.md](README.md). Утверждённые числа: `tools/diar_eval/baseline.json`.

## 1. Цель

Проверить на открытых данных четыре свойства приложения:

1. Качество расшифровки русской и многоязычной речи.
2. Качество диаризации: кто и когда говорил.
3. Качество привязки слов к спикерам.
4. Скорость, память и устойчивость на длинных записях.

Отдельная цель - заменить калибровку порогов «на слух» измерением. Сюда относятся `AUTO_K_GAP`, `CENTROID_MERGE_SIM`, порог AHC (agglomerative hierarchical clustering, иерархическая кластеризация) `0.52`, порог сопоставления профилей `0.45` и порог перекрытия `0.35`.

## 3. Что проверяем

| Слой | Проверка | Метрика |
|---|---|---|
| Расшифровка | Текст против эталона | WER, CER |
| Диаризация | Границы реплик и число спикеров | DER, SCA |
| Атрибуция | Слово против своего спикера | cpWER, attribution accuracy |
| Производительность | Время и память | RTF, peak RSS |
| Устойчивость | Падения, потеря слов, формат | 100% файлов без сбоев |

### 3.1. Расшифровка

Основная метрика - WER (word error rate, доля ошибок в словах). Дополнительно считаем CER (character error rate, доля ошибок в символах).

Правила нормализации текста фиксируем до первого прогона:

- Unicode NFKC (нормализация совместимости), нижний регистр.
- `ё` заменяем на `е`.
- Удаляем пунктуацию, кроме пробелов.
- Схлопываем повторные пробелы.
- Числа не разворачиваем в слова. Отдельно отмечаем файлы, где эталон содержит цифры.
- Не удаляем слова-паразиты и повторы: они входят в WER.

WER считаем по сумме ошибок на всех файлах (micro-average), а не как среднее по файлам. Доверительный интервал 95% считаем бутстрэпом по файлам, 1000 повторов.

### 3.2. Диаризация

Основная метрика - DER (diarization error rate, доля ошибок диаризации). Формула:

`DER = (miss + false alarm + confusion) / reference_speech`

Условия отчёта:

- Основной режим: `collar=0.0`, `skip_overlap=False`.
- Дополнительный режим: `collar=0.25`, `skip_overlap=False` - для сравнения с публикациями.
- Третий режим: `collar=0.0`, `skip_overlap=True` - чтобы отделить ошибки на перекрытиях.

SCA (speaker count accuracy, точность числа спикеров) - доля файлов, где число предсказанных спикеров совпало с эталоном. Дополнительно считаем MAE (mean absolute error, среднюю абсолютную ошибку числа спикеров).

### 3.3. Атрибуция слов

Нужны две метрики.

**cpWER (concatenated minimum-permutation WER).** Слова группируем по спикерам. Для каждой пары потоков считаем расстояние редактирования. Минимизируем сумму ошибок при взаимно однозначном сопоставлении потоков. Делим на общее число эталонных слов. Недостающие потоки дополняются пустыми: это учитывает удаления и вставки. Потоки разных спикеров не объединяются перед выравниванием. Минимум находится венгерским алгоритмом; действующий предел - 8 спикеров. Метрика штрафует и за ошибку текста, и за чужого спикера. Корректная реализация помечена `speaker-stream-v2`. Старые значения без версии требуют пересчёта и напрямую с ней не сравниваются.

**Attribution accuracy (точность атрибуции).** Совмещаем слова гипотезы и эталона выравниванием Левенштейна. На совпавших словах строим матрицу «спикер гипотезы - спикер эталона», назначаем спикеров алгоритмом Хунгарда и считаем долю слов с верным спикером. Метрика считается только на файлах с двумя и более спикерами.

### 3.4. Производительность

- RTF (real-time factor) = время обработки / длительность аудио. Считаем в release-сборке.
- Отдельно фиксируем время загрузки моделей, VAD, ASR, диаризации и записи JSON.
- Peak RSS (пиковое потребление памяти) снимаем через `/usr/bin/time -v` или аналог для macOS и Windows.
- Эталонная машина: 8 виртуальных ядер, 16 ГБ памяти, SSD, без графического ускорения. Для GPU-провайдеров - отдельная строка отчёта.

### 3.5. Устойчивость

- Приложение обрабатывает 100% файлов без падения и без таймаута.
- `.transcript.json` проходит `validate`: нет NaN, нет слов без времени, нет неизвестных спикеров.
- Ни одно слово из эталона не теряется в отчёте `stats.words`, кроме случаев, где ASR вернул пустой текст.
- Нет записи за пределы каталога данных.
- Нет сетевых запросов, кроме проверки обновлений по явному действию.

## 4. Датасеты

Делим на три уровня. Уровень 1 обязателен для релиза. Уровень 2 нужен для калибровки и русской специфики. Уровень 3 - задел.

### 4.1. Уровень 1: обязательные наборы

| Набор | Язык | Объём для теста | Задача | Лицензия | Роль |
|---|---|---|---|---|---|
| Golos, Crowd test | русский | 11,2 ч | ASR | лицензия Golos, проверить перед публикацией | основная русская проверка |
| Golos, Farfield test | русский | 1,4 ч | ASR | лицензия Golos | дальнее поле, шум |
| Common Voice, русский test | русский | фиксированный релиз | ASR | CC0 | вне домена обучения |
| FLEURS, `ru_ru` test | русский | официальный test | ASR | CC BY 4.0 | вне домена, чистая студия |
| Russian LibriSpeech, test | русский | выборка 2 ч | ASR | public domain (США) | аудиокниги, один диктор |
| FLEURS, `en_us`, `de_de`, `fr_fr`, `es_419`, `cmn_hans_cn` test | пять языков | по 1 ч | ASR Whisper | CC BY 4.0 | многоязычность |
| AMI, IHM test | английский | официальный test | диаризация | CC BY 4.0 | совещание, головные микрофоны |

| AISHELL-4, test | китайский | официальный test | диаризация | CC BY-SA 4.0 | конференция, 4-8 спикеров |
| AliMeeting, Test far | китайский | 20 встреч | диаризация | CC BY-SA 4.0 | совещание, 2-4 спикера |
| VoxConverse v0.3, test | английский | официальный test | диаризация | CC BY 4.0 | видео, перекрытия |

Для AMI используем публичный набор разметки `BUTSpeechFIT/AMI-diarization-setup` и вариант `only_words`. Для AISHELL-4 и AliMeeting берём официальные аннотации. Для VoxConverse - RTTM версии 0.3.

Команды скачивания FLEURS и ссылки на Golos, AMI и VoxConverse: [README.md](README.md), раздел «Как получить данные».

Подготовка многоканальных наборов: берём канал 1 микрофонного массива, приводим к 16 кГц и моно. Для AMI IHM используем готовый микс головных микрофонов. Для AISHELL-4 выбираем тот же вариант микса, что в публичных бенчмарках, и фиксируем команду подготовки в `datasets.yaml`.

Русские наборы проверяем основным движком GigaAM v3 RNNT. Whisper turbo запускаем на выборке 2 ч из Golos Crowd и FLEURS `ru_ru` как контрольный движок. Многоязычные наборы проверяем только Whisper turbo. Hotwords и CTC по умолчанию выключены; их проверяем отдельным сценарием.

### 4.2. Уровень 2: русские встречи и стресс

Мне не известен открытый русский корпус встреч с эталонной разметкой «кто и когда». Если кто-то знает такой - прошу открыть issue со ссылкой, лицензией и условиями доступа. В доступных мне Golos и OpenSTT нет идентификаторов спикеров, а записи короткие. Поэтому сейчас русскую диаризацию проверяем на синтетическом наборе `RuMeet-Synth` и фиксируем это ограничение.

**RuMeet-Synth** собираем из открытых русских источников:

- Common Voice, русский: группируем реплики по `client_id`, это приблизительный идентификатор диктора.
- Russian LibriSpeech: один диктор на книгу, если метаданные это подтверждают.
- Golos: только как источник речи для проверки устойчивости, без разметки спикеров.

`client_id` не гарантирует одного человека: один диктор может записываться с разных клиентов. Для сравнения версий это допустимо, для абсолютных выводов - нет.

Сценарии синтеза:

| Параметр | Значения |
|---|---|
| Длительность | 5, 15, 30 мин |
| Спикеры | 2, 3, 4, 5-6 |
| Пауза между репликами | 0, 0,2, 0,5 с |
| Перекрытие | 0%, 5%, 15% |
| Шум | чистый, SNR 20, 10, 5 дБ |
| Канал | моно, стерео с разделением спикеров по каналам |

Для каждого файла генерируем RTTM, эталонный текст и JSON с параметрами. Зерно генератора фиксируем. Набор помечаем как синтетический: абсолютные цифры DER нельзя сравнивать с публикациями, но можно сравнивать версии между собой.

Отдельный стерео-сценарий проверяет путь «микрофон и системный звук». Спикеров делим на два канала, смешиваем в один файл и проверяем, что приложение вернуло исходное разделение.

### 4.3. Уровень 3: задел

- DIHARD III - только при наличии лицензии LDC. Набор сложный, но закрытый.
- NOTSOFAR-1 - требует регистрации, добавить при появлении доступа.
- OpenSTT `public_speech`, выборка 50 ч - шумный YouTube, лицензия CC BY-NC, только тест без публикации аудио.
- MUSAN или другой открытый шум - для синтетических сценариев, лицензию проверить отдельно.

### 4.4. Что не берём

- CALLHOME - закрытая лицензия LDC.
- RAMC (MagicData-RAMC) - китайский телефонный корпус, не русский.
- M3SD - псевдоразметка, не эталон.
- Любые наборы, где аудио нельзя скачать без регистрации или оплаты, - в обязательный уровень не входят.

### 4.5. Эталон синтетических встреч

Разные файлы FLEURS не гарантируют разных дикторов. Поле `id` в TSV обозначает предложение, а не человека. [Официальная статья FLEURS](https://simran-khanuja.github.io/assets/fleurs_slt.pdf) подтверждает, что каждое предложение записали три разных носителя языка. На это опирается выборка `prepare_fleurs_speakers.py`. Порядок отбора детерминирован: сначала числовой sentence ID, затем имя файла. Модель и cosine в отборе не участвуют. Для 3-4 разных дикторов с разными предложениями локальные метаданные не дают достаточного доказательства, поэтому такие основные сценарии не создаются.

Каноническое доказательство отбора - `tools/diar_eval/proof-fleurs-regression.json`: sentence ID, gender, число отсчётов и SHA-256 клипов. Аудио и текст в репозиторий не попадают. Встречи с метками клипов сохраняются для сравнения версий, но их SCA - точность воспроизведения меток, а не точность различения реальных людей. Менять эталон ради улучшения метрики нельзя.

## 5. Выборка и разбиение

1. Для небольших наборов берём всю официальную тестовую выборку.
2. Для больших наборов - стратифицированную выборку: по 100 файлов на условие, зерно `20261109`.
3. Условия стратификации: длительность, число спикеров, доля перекрытия, канал, уровень шума.
4. Наборы для калибровки и финального отчёта не пересекаются:
   - калибровка: dev или eval части, плюс `RuMeet-Synth`;
   - финальный отчёт: официальный test, один раз на релиз.
5. Официальные test не используем для обучения, дообучения и подбора гиперпараметров.
6. После финального прогона пороги не меняем. Иначе это уже другой эксперимент, и его нужно перезапустить.

## 6. Стенд и автоматизация

Стенд - `tools/diar_eval`. Python в рантайм приложения не попадает.

| Файл | Назначение |
|---|---|
| `datasets.yaml` | список наборов, ссылки, лицензии, правила подготовки |
| `prepare_fleurs_speakers.py` | проверенная выборка FLEURS и `proof.json` |
| `prepare_main_meetings.py` | основной EN/RU 2spk-набор normal/quiet |
| `run_batch.py` | запускает release-сборку по манифесту, сохраняет метрики, RTTM и снимки входов |
| `run_suite.py` | запуск `small`/`full` suite по JSON-описанию |
| `check.py` | детерминированная сверка `metrics.csv` с `baseline.json` |
| `metrics.py` | WER, CER, DER, SCA, cpWER v2, attribution accuracy |
| `report.py` | `report.md`, доверительные интервалы, сравнение с `baseline.json` |
| `regression.py` | короткий регрессионный порог на синтетических встречах |
| `suites/*.json` | `small` и `full` наборы |
| `baseline.json` | единая точка отсчёта: `suites`, `groups` и `metrics` |
| `requirements-eval.txt` | закреплённые версии `pyannote.metrics`, `jiwer`, `numpy` |

Два основных набора; всё остальное - отдельные релизные проверки:

| Набор | Когда | Состав | Время |
|---|---|---|---|
| `small` | перед каждым пул-реквестом | 6 синтетических встреч и 4 основных файла | минуты |
| `full` | перед релизной веткой | `small`, русская матрица 36 и 450 файлов русского распознавания речи | десятки минут или часы |
| release | перед релизом | `full`, VoxConverse, AMI, записи 60 и 120 минут, macOS и Windows | отдельное решение |

`run_suite.py --suite small|full` запускает набор. `check.py` сверяет результат с `baseline.json`. `small` не заменяет `full`: он ловит грубые поломки, но не покрывает матрицу 3-4 спикеров и длинный ASR.

Диагностика (абляции, разбор стадий) не входит в порог и не хранится в репозитории как отдельные документы.

Требования к запуску:

- Release-сборка, не отладочная.
- Один файл - один процесс. Так проще отделить загрузку моделей от обработки.
- Первый файл каждого набора не исключаем из RTF: отдельного прогрева нет. Для холодного старта делаем отдельный замер.
- Модели и их SHA-256 берём из `models-manifest.json`; версия приложения - из `PODTEKST_GIT_COMMIT`.
- Логи в `MR_LOG_FORMAT=jsonl`, артефакты - через `--dev`.
- Все результаты пишем в `runs/<name>/`, аудио и эталоны в git не попадают.
- `run_batch.py` сохраняет `transcript_snapshot` и `reference_snapshot`; метрики считаются по ним.

## 7. Порядок прогона

1. Заморозить кандидата на релиз: commit, версии моделей, SHA-256.
2. Подготовить наборы и проверить SHA-256.
3. Прогнать дымовой тест: по два файла из каждого набора. Проверить, что метрики считаются и отчёт собирается.
4. Прогнать калибровочные наборы. Менять только пороги, не модели. Каждое изменение фиксировать в отчёте.
5. Прогнать официальные test один раз. Записать метрики.
6. Прогнать `RuMeet-Synth` по матрице сценариев.
7. Прогнать длинные записи: 60 и 120 мин, моно и стерео. Замерить RTF и peak RSS.
8. Повторить дымовой тест на macOS и Windows.
9. Собрать отчёт и сравнить с baseline.
10. Передать отчёт на ревью и решить, выпускать ли релиз.

## 8. Критерии приёмки

Значения ниже - целевые. После первого полного прогона их нужно утвердить или снизить с записью в отчёте. Нельзя тихо подменять цель фактическим результатом.

Русские строки относятся к GigaAM v3 RNNT, многоязычные - к Whisper turbo.

### 8.1. Расшифровка

| Набор | Цель WER | Примечание |
|---|---|---|
| Golos Crowd test | ≤ 8% | вероятно, домен обучения, это проверка регресса |
| Golos Farfield test | ≤ 16% | дальнее поле |
| Common Voice, русский | ≤ 15% | вне домена |
| FLEURS `ru_ru` | ≤ 12% | чистая студия |
| Russian LibriSpeech | ≤ 10% | аудиокниги |
| FLEURS `en_us` | ≤ 8% | Whisper turbo |
| FLEURS `de_de`, `fr_fr`, `es_419` | ≤ 12% | Whisper turbo |
| FLEURS `cmn_hans_cn` | ≤ 18% | Whisper turbo |

### 8.2. Диаризация

| Набор | Цель DER | Примечание |
|---|---|---|
| AMI IHM | ≤ 20% | 4 спикера, головные микрофоны |
| AMI SDM | ≤ 30% | микрофонный массив |
| AISHELL-4 | ≤ 16% | 4-8 спикеров, перекрытия |
| AliMeeting far | ≤ 28% | 2-4 спикера |
| VoxConverse v0.3 | ≤ 16% | видео, сильные перекрытия |
| `RuMeet-Synth` | baseline + 5% | только сравнение версий |

SCA:

- 2-4 спикера: точное число не меньше чем в 80% файлов.
- 5-8 спикеров: не меньше чем в 60% файлов.
- MAE числа спикеров: не больше 0,5.

### 8.3. Атрибуция

- Attribution accuracy: не меньше 85% для 2-4 спикеров и не меньше 75% для 5-8.
- cpWER: не больше WER того же набора плюс 8 процентных пунктов.
- На файлах с перекрытием 15% допускается падение accuracy на 10 процентных пунктов относительно файлов без перекрытия.

### 8.4. Производительность и устойчивость

- Для моно 1 ч RTF не больше 0,5. Для стерео 1 ч - не больше 0,7. Замеры на эталонной машине.
- Peak RSS не больше 4 ГиБ.
- 100% файлов обработаны без падения.
- 0 нарушений схемы `.transcript.json`.
- 0 потерянных слов, кроме пустых ответов ASR.

### 8.5. Цель релиза, порог регресса и известный разрыв

Это разные вещи, их нельзя смешивать:

- **Цель релиза** - абсолютные значения из 8.1-8.4. Это ориентир, а не автоматический блокер каждого пул-реквеста.
- **Порог регресса** - проверка `small` и `full` по `baseline.json`. Метрика не должна быть хуже базовой линии. Жёсткие проверки: 0 падений, схема, точное число спикеров на 2spk, attribution на main.
- **Известный разрыв** - подтверждённый разрыв, который не закрыт и перечислен в `baseline.json`. Он не должен выглядеть зелёным и не должен молча блокировать слияние.

Текущие известные разрывы: 3-4 спикера, обычная английская стресс-пара, VAD-пропуски на main. Они фиксируются в `baseline.json`.

## 9. Регрессионная политика

Базовая линия (baseline) - точка отсчёта для сравнения версий, а не разрешение на релиз.

`small`:

- 0 падений процесса;
- метрики посчитаны, схема `.transcript.json` валидна;
- `check.py --suite small` детерминированно сверяет 10 файлов с базовой линией;
- русское ухудшение блокирует слияние.

`full`:

- всё из `small`;
- русская матрица 36 и 450 файлов русского распознавания речи;
- **русский язык - жёсткий блокер:** любое ухудшение WER, CER, DER, SCA, cpWER v2 или attribution запрещает слияние;
- если русская метрика улучшилась, новое значение записывается в `baseline.json` в этом же пул-реквесте;
- английский проверяется и публикуется, но известные разрывы не блокируют русский приоритет.

Цели релиза из 8.1-8.4 применяются, когда цель официально принята. До этого они остаются ориентиром и не заменяются фактическим результатом.

Базовая линия хранится только в `tools/diar_eval/baseline.json`. В нём есть `suites.small`, `suites.full`, `groups` для `report.py` и `metrics` + `proof_sha256` для `regression.py`. Базу обновляем только вместе с новым прогоном.

Правило пул-реквеста:

1. Прогнать `small` на финальном бинарнике.
2. Сравнить с `baseline.json` через `check.py`.
3. Любое русское ухудшение - исправить или не сливать.
4. Улучшение - обновить `baseline.json` в том же пул-реквесте.
5. Перед релизной веткой прогнать `full`; перед релизом - релизные проверки.
6. Историю прогонов в репозитории не хранить: только текущую базовую линию.

## 10. Артефакты

На каждый прогон:

```text
runs/<name>/
  manifest.json          commit, грязное дерево, ОС, CPU, RAM, SHA моделей и наборов
  metrics.csv            строка на файл: набор, условие, WER, CER, DER, SCA, cpWER, accuracy, RTF, RSS
  report.md              таблицы, выводы, сравнение с baseline
  rttm/                  гипотезы для DER
  transcripts/           точные снимки транскриптов
  references/            точные снимки эталонов
  logs/                   stdout/stderr каждого файла
  failures/              логи только для упавших файлов
```

В git коммитим:

- `tools/diar_eval/datasets.yaml`;
- `tools/diar_eval/proof-fleurs-regression.json`;
- `tools/diar_eval/baseline.json`;
- скрипты и `requirements-eval.txt`.

Не коммитим: аудио, эталонные RTTM, полные транскрипты, логи с путями и текстом.

## 12. Лицензии и приватность

- В репозиторий попадают только скрипты, манифесты и агрегированные метрики.
- Аудио и эталонные транскрипты храним вне git, в каталоге `runs/`, который игнорируется.
- Перед публикацией цифр проверяем лицензию каждого набора. Для Golos и OpenSTT условия ограничивают коммерческое использование и распространение.
- CC BY-SA наборы (AISHELL-4, AliMeeting) требуют указания авторства и сохранения лицензии на производные материалы.
- Персональные записи, имена и фрагменты речи не используем. Это правило P12 действует и для тестов.
- Аудио и эталоны храним только на время цикла тестирования. После утверждения отчёта удаляем их или переносим на защищённый носитель.
- Ссылки на наборы и лицензии включаем в `datasets.yaml` и в отчёт.

## 13. Риски и ограничения

| Риск | Что делаем |
|---|---|
| Открытый русский корпус встреч с эталоном мне не известен | используем `RuMeet-Synth`; если кто-то знает корпус - issue со ссылкой и лицензией |
| Пересечение обучающих и тестовых данных | помечаем наборы как «в домене» и «вне домена», не сравниваем их напрямую |
| Диаризация на китайском и английском | считаем акустическую задачу языконезависимой, но выводы ограничиваем |
| Синтетика отличается от живых встреч | используем только для сравнения версий, не для абсолютных обещаний |
| Разные версии ONNX Runtime на CPU | фиксируем версию, ОС и CPU в manifest |
| Шум измерений на слабом CPU | RTF считаем на эталонной машине, на остальных - только дымовой тест |
| Нормализация текста меняет WER | правила зафиксированы в разделе 3.1 и не меняются внутри прогона |
| Лицензии запрещают публикацию примеров | публикуем только агрегаты и ссылки |

## Приложение A. Формулы

**WER:**

`WER = (S + D + I) / N`

где `S` - замены, `D` - удаления, `I` - вставки, `N` - число слов эталона.

**CER:** то же на символах.

**DER:**

`DER = (miss + false_alarm + confusion) / reference_speech`

**cpWER:** `min_π Σ_s ED(R_s, H_π(s)) / Σ_s |R_s|`, где `R_s` и `H_s` - отдельные потоки слов каждого спикера, пустые потоки дополняют отсутствующих спикеров. Выравнивание не пересекает границы потоков. Значение может превышать 100% из-за вставок.

**Attribution accuracy:** доля верных спикеров на словах, которые совпали с эталоном после выравнивания.

**RTF:** `время_обработки / длительность_аудио`.

## Приложение B. Команды

Подготовка одного файла:

```bash
./run.sh --transcribe /data/ami/ES2002a.wav --engine gigaam
```

Перевод транскрипта в RTTM:

```bash
python3 tools/diar_eval/transcript_to_rttm.py ES2002a.transcript.json ES2002a.rttm --id ES2002a
```

Расчёт DER:

```bash
python3 tools/diar_eval/evaluate.py reference/ES2002a.rttm ES2002a.rttm --per-file
```

Подготовка и прогон:

```bash
ROOT="${MR_DIAR_BENCH_ROOT:-$HOME/.cache/podtekst-bench}"
PY="$ROOT/venv/bin/python"
"$PY" tools/diar_eval/prepare_fleurs_speakers.py "$ROOT"
"$PY" tools/diar_eval/prepare_main_meetings.py "$ROOT"

OUT="$ROOT/runs/small"
"$PY" tools/diar_eval/run_suite.py --suite small --out "$OUT"
"$PY" tools/diar_eval/check.py --suite small --run "$OUT/metrics.csv"
```

`report.py` запускается для `full`-прогона: его `groups` в baseline относятся к полному набору.
