# Русский язык: основной приоритет

Порядок работы: русский ASR → атрибуция русского текста и потери голосов →
русская матрица → английская совместимость последней. EN partial v1 остаётся
отдельным уточнением эталона, не заменяет исходные значения и не является
baseline. В этой итерации ASR, VAD, экстрактор и пороги не менялись.

## Что известно по сохранённому N

| Русский набор | Результат |
|---|---|
| Golos Crowd 300 | WER 13,68%; нормализованный WER 6,45% |
| Golos Farfield 100 | WER 8,72%; нормализованный WER 6,18% |
| FLEURS RU 50 | WER 5,54%; нормализованный WER 4,65% |
| Main RU normal / quiet | 2 → 2; attribution 100%; DER 18,95% / 18,20% на прежнем полном RTTM |
| Матрица, 2 голоса | 10 из 12 находят 2 голоса; два случая 2 → 1 |
| Матрица, 3 голоса | 8 из 12 находят 3 голоса; четыре случая 3 → 2 |
| Матрица, 4 голоса | 1 из 12 находит 4 голоса; одиннадцать случаев 4 → 3 |

SHA-256 источников всех 36 строк матрицы сверены с
`diar-regression-clips/proof.json`. Это подтверждённый по протоколу FLEURS
стресс-набор: разные записи одного предложения соответствуют разным дикторам,
между группами используется различие metadata gender. Одинаковый текст
усложняет задачу, но не отменяет потери голосов. Его нельзя объявлять
неподтверждённым только из-за отсутствия глобальных speaker ID.

В локальных Golos parquet присутствуют `id, audio, text, duration`, но нет
подтверждённого speaker ID. Другого локального RU-корпуса для 3–4 дикторов с
разными предложениями не найдено. Sentence ID FLEURS и audio ID Golos нельзя
выдавать за идентификатор диктора.

## Исправление cpWER — прежде следующей оценки диаризации

Прежний `metrics.py` группировал слова по спикерам, затем объединял потоки
перед одним выравниванием. Например, два диктора произнесли по «альфа бета»,
а гипотеза отдала все четыре слова одному голосу: старый расчёт мог дать 0%.

В `speaker-stream-v2` расстояния редактирования считаются отдельно для каждой
пары потоков. Венгерский алгоритм минимизирует сумму ошибок; отсутствующие
потоки дополняются пустыми. В примере потеря потока даёт два удаления и две
вставки, то есть 4 ошибки на 4 эталонных слова. Значение может превышать 100%.
Число потоков по-прежнему ограничено восемью.

Поэтому прежние cpWER матрицы 18,67% / 18,02% / 12,51% нельзя использовать
для вывода об улучшении атрибуции без пересчёта. Исходные таблицы сохраняются;
WER, CER, DER, SCA и attribution этим исправлением не меняются.
Новые CSV/манифесты содержат `cpwer_version`. Отчёт отвергает смешивание версий
и не объявляет регресс/улучшение при сравнении v2 с baseline без этой версии.

Даже корректный cpWER не различает перестановки одинакового текста при
одинаковых итоговых потоках. Для стресс-пар по-прежнему нужны DER, SCA и
временная атрибуция, а не один показатель текста.

## Короткая проверка пользователем, без инференса

Тесты добавлены, но агент их не запускал:

```bash
ROOT="$HOME/.cache/podtekst-bench"
PY="$ROOT/venv/bin/python"
"$PY" -m unittest discover -s tools/diar_eval -p 'test_*.py'
```

Пересчитать только RU cpWER по сохранённым main-гипотезам:

```bash
OUT="$ROOT/runs/ru-cpwer-v2-$(date +%Y%m%d-%H%M%S)"
for variant in normal quiet; do
  "$PY" tools/diar_eval/rescore_cpwer.py \
    --run "$ROOT/runs/n-combination-20261112-210124/default-main-$variant" \
    --manifest "$ROOT/diar-main-meetings/$variant.json" \
    --out "$OUT/main-ru-$variant.csv"
  "$PY" tools/diar_eval/report.py --csv "$OUT/main-ru-$variant.csv" \
    --out "$OUT/main-ru-$variant.md"
done
```

По умолчанию `rescore_cpwer.py` выбирает русский. Он использует точный снимок
транскрипта либо скопированный `dev_run/transcript/post.json`, сохраняет
старые cpWER-поля, SHA-256 и происхождение входов. Другие метрики копируются
без изменения, исходный CSV не переписывается, существующий `--out` отклоняется.

В старом полном прогоне матрицы N копий JSON может не быть. Текущие sidecar
JSON допускаются только явно и при совпадении геометрии с сохранённым RTTM:

```bash
"$PY" tools/diar_eval/rescore_cpwer.py --run "$ROOT/runs/n-round/matrix" \
  --manifest "$ROOT/runs/matrix-m/manifest.json" --allow-live-transcripts \
  --out "$OUT/matrix-ru-live-geometry-checked.csv"
```

Этот флаг допустим, только если текущие JSON действительно относятся к N.
Совпадение времени и меток RTTM не доказывает неизменность слов. Перезаписанный
текст старого кандидата таким способом не восстанавливается. В новых прогонах
`run_batch.py` всегда сохраняет точные `transcript_snapshot` и
`reference_snapshot` и считает метрики именно по этим копиям.

## Следующий пакет русской диагностики

Без инференса подготовлены отдельные входные манифесты в
`$ROOT/manifests/ru-priority-v1/`:

- `main-ru.json`: два main RU случая, normal и quiet.
- `matrix-ru6.json`: 2/3/4 голоса × равные/−18 дБ, 60 с, без перекрытий.

Это выбор по условиям сценария, не по результату модели. Аудио, исходные
RTTM и полный манифест не менялись. Если нужны стадийные данные для следующей
правки, достаточно этих восьми RU-файлов на сохранённом N:

```bash
APP="$ROOT/runs/n-combination-20261112-210124/podtekst"
export PODTEKST_DATA_DIR="$ROOT/appdata" MR_DIAR_BENCH=1 MR_DIAG_DUMP=1 MR_LOG_TEXT=off
export MR_LOG='info,run=debug,vad=debug,diar=debug,cluster=debug'
unset MR_DIAR_EXPERIMENT
for suite in main-ru matrix-ru6; do
  "$PY" tools/diar_eval/run_batch.py --app "$APP" \
    --manifest "$ROOT/manifests/ru-priority-v1/$suite.json" \
    --out "$OUT/$suite" --dev-runs-dir "$ROOT/appdata/logs/dev-runs"
done
```

Отдельный старый стресс-gate доступен через `regression.py --language ru`;
полный режим сохраняет все шесть сценариев, но сначала запускает четыре RU,
потом два EN. Пороги и приёмка не ослаблены.

ASR450 повторяется при изменении ASR-сигнала или декодера, а не ради исправления
формулы метрики. Следующая алгоритмическая правка должна устранять конкретный
этап потери русского голоса, подтверждённый стадийными данными. До этого новый
baseline не объявляется.
