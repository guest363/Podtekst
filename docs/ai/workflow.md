# Регламент работы с ИИ

Инструкции — часть репозитория и обновляются вместе с кодом. Карта проекта — `AGENTS.md`,
правила — `docs/ai/code-style.md`, домен — `CONTEXT.md`, архитектура —
`docs/architecture.md`. Этот файл описывает процесс и критерий готовности; команды живут
в `./scripts/verify.sh` и здесь не дублируются.

## Два трека

### Track 1 — обычные задачи (по умолчанию)

Исправления, точечные доработки UI, тесты, рефакторинг без изменения существующих
контрактов.

1. Минимальный diff (P2), причина — на своём слое (P10).
2. Нетривиальное проектное решение: до кода 2–5 строк с вариантами и trade-offs.
3. По ходу работы — затронутые режимы `verify.sh`, перед завершением — `--all`.

### Track 2 — архитектурные и критические изменения

Триггеры:

- схема сохранения данных (`voiceprints.json` v3, `.transcript.json`);
- контракт HTTP REST или IPC между Rust и Web UI;
- новая нейросетевая модель или замена аудиодвижка;
- флаги запуска CLI и переменные окружения (P9).

Порядок:

1. До кода: цель, два варианта реализации, влияние на обратную совместимость.
2. Human approval: редактирование начинается только после одобрения.
3. Синхронно обновить `CONTEXT.md`, `docs/architecture.md` и `AGENTS.md` затронутых зон.

## Верификация

Единая точка входа — `./scripts/verify.sh`; её вызывают `lefthook` и CI. Режимы:

| Режим | Что проверяет |
|---|---|
| `--fast` | P11-аудит комментариев, бюджеты и ссылки инструкций |
| `--docs` | То же, без P11 |
| `--rust` | `cargo fmt --check`, `clippy -D warnings`, тесты workspace |
| `--ui` | `yarn lint`, `yarn check`, `yarn build`, пересчёт штампа статики |
| `--tauri` | `clippy` с `tauri-ui` (нужны системные WebKit-пакеты) |
| `--all` | Всё перечисленное |

Рабочий цикл: `--fast` после правок, затронутый режим по ходу, `--all` перед PR. Если
полный прогон невозможен (нет WebKit, Node-зависимостей или окружения для живых тестов),
укажите это явно — успешный сокращённый прогон не выдаётся за полный.

Живые ONNX-тесты: `MR_MODELS_DIR` + `MR_TEST_WAV`. Каталог данных —
`MEETING_RECORDER_DATA_DIR`. Секреты и личные записи в тесты не попадают (P12).

## Критерий готовности

Задача завершена, когда:

- гейт зелёный, а diff минимален и не трогает соседний рабочий код;
- поведение покрыто тестом либо в ответе указано, чем проверено и что осталось непроверенным;
- затронутые `AGENTS.md`, `CONTEXT.md`, `docs/architecture.md` обновлены;
- в ответе перечислено: что изменено, какие режимы прошли, какие ограничения остались.

Не объявляйте непройденные проверки успешными и не расширяйте задачу до ремонта всего
репозитория: несвязанные ошибки сообщаются отдельно.

## Zero-Leak перед коммитом

- В `git status` и `git diff` нет `people.json`, `voiceprints.json`, `config.json`, записей,
  логов и скачанных моделей.
- В коммитах, PR и отчётах нет имён людей, тем бесед и реальных названий файлов — только
  обезличенные параметры записи (P12).
- Исходящий трафик — только веса моделей, проверка релиза и загрузка обновления по явному
  согласию пользователя.

## Артефакты

- Спеки фич (по образцу уже существующих): `docs/features/<фича>/SPEC.md` и
  `VERIFICATION.md`.
- Локальные контексты: `*/AGENTS.md` — только при существенных правилах, по шаблону
  `docs/ai/agents-template.md`.
