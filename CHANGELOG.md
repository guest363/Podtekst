# Changelog

Все заметные изменения проекта. Формат - [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии - [Semantic Versioning](https://semver.org/lang/ru/).

## [Неопубликовано]

### Добавлено

* Живой захват звука на Windows (WASAPI, shared mode): микрофон в левый канал,
  loopback системного звука — в правый, тот же контракт, что на Linux и macOS.
  Формат микшера сводится в моно и ресемплируется в 16 кГц; дорожка системного
  звука добирается тишиной, пока воспроизведения нет, — каналы остаются
  синхронными на любой длине записи.
* Каталог устройств Windows: микрофоны и выходы (их loopback — источники
  системного звука) с именами, состоянием «заглушено» и устройствами по
  умолчанию.
* Скачивание ffmpeg из интерфейса (Настройки → Модели ИИ): публичная сборка
  с GitHub загружается с прогрессом, распаковывается встроенным `tar` в
  `<данные>/bin` и подхватывается ядром без перезапуска. Карточка поясняет,
  для чего ffmpeg нужен; при неудаче — ссылка на ручную установку.
* Запись экрана на Windows: захват рабочего стола через `ffmpeg gdigrab`
  (кодировщик libx264, при его отсутствии — аппаратный h264_mf), склейка с аудио
  в MP4 тем же конвейером, что и на Linux. Переключатель появляется, когда ffmpeg
  с кодировщиком H.264 доступен.

### Исправлено

* Размер докачки моделей в интерфейсе больше не зашит в код: кнопка
  «Скачать базовые модели» и бейджи карточек показывают фактический остаток
  (полный размер минус уже скачанные файлы), а не константу ~306 МБ.
* Предупреждения Clippy при сборке на Windows: диалог сохранения теперь
  использует фильтр вызывающей стороны, убраны лишние `return` в desktop.rs,
  снято ложное срабатывание dead_code для `CaptureStream::spawn` на платформах
  без живого бэкенда.
* Поддержка записи экрана на Windows переоценивается после установки ffmpeg
  из интерфейса — переключатель включается без перезапуска приложения.

## [0.1.6] - 2026-10-30

### Добавлено

* Синхронная запись экрана рабочего стола (Linux): нативная интеграция с D-Bus
  GNOME Shell Screencast (`org.gnome.Shell.Screencast`) с аппаратным H.264-кодированием.
  Видеоряд записывается параллельно с раздельным захватом звука (микрофон + собеседники)
  без нагрузки на процессор.
* Автоматическая сборка мультимедиа-контейнера MP4: при остановке записи аудиодорожки
  и видеоряд моментально склеиваются через встроенный конвейер ffmpeg (`-c:v copy -c:a aac -shortest`)
  с сохранением исходного качества без пережатия.
* Интегрированный видеоплеер в интерфейсе расшифровки: синхронный просмотр видеозаписи
  со звуком, таймкодами реплик, спикерами и возможностью перехода по клику на реплику.
* Переключатель режима записи экрана в контрольной панели («Включить запись экрана» /
  «Запись экрана включена» / «Запись экрана идёт»).

## [0.1.5] - 2026-10-29

### Добавлено

* Интеграция PyAnnote Segmentation 3.0 (ONNX Powerset): высокоточное обнаружение
  перекрывающейся речи (overlapped speech) со скользящим окном 10 с и шагом 1 с.
* Очистка эмбеддингов спикеров (Overlap Masking): перед извлечением векторов
  голоса моделью ERes2NetV2 фреймы одновременной речи маскируются, исключая
  смешивание характеристик голосов в кластерных центроидах.
* Венгерский алгоритм сопоставления спикеров (Speaker Assignment): связывание
  локальных меток окон сегментации с глобальными кластерами реплик с соблюдением
  лимита `max_speakers`.
* Экспорт в DOCX с нативным системным диалогом сохранения: вызов платформенного
  окна «Сохранить как...» через `zenity` (Linux GTK/GNOME, fallback на `kdialog`),
  `osascript` (macOS) и PowerShell `SaveFileDialog` (Windows), либо через
  File System Access API (`showSaveFilePicker`) в современных браузерах.
* Единые метаданные встречи для буфера обмена («Копировать текст»), экспорта DOCX
  и печати/сохранения в PDF: заголовок, источник, хронометраж, список участников
  с их ролями/должностями из каталога и разделительная линия.
* Интерактивное редактирование расшифровки в Web UI: клик по тексту реплики для
  быстрого исправления, всплывающее меню управления спикером (переименование во
  всей встрече и назначение), поиск по тексту с подсветкой вхождений.

### Исправлено

* Синхронизация подсветки аудиоплеера: устранено отставание на 2–5 с при
  наложении речи нескольких спикеров за счёт выбора активной реплики по
  наибольшему `start <= currentTime`.
* Устранено избыточное дробление спикеров (over-clustering): неназначенные локальные
  треки окон PyAnnote привязываются к свободным глобальным кластерам при схожести
  векторов >= 0.35 вместо создания новых сущностей; порог агломеративной
  кластеризации сбалансирован до 0.52.

## [0.1.4] - 2026-10-28

### Исправлено

* Моно-диаризация: минимальный порог нарезки фрагментов и core-кластеризации
  снижен до 0.6 с (`CORE_MIN_DUR = 0.6`, `MIN_UNIT_SEC = 0.6`). Короткие
  реплики-ответы второго спикера (0.6–1.0 с) больше не склеиваются с речью
  первого спикера и корректно формируют собственный кластер.
* Защита от избыточного дробления непрерывной речи: пятиточечное сглаживание RMS
  с порогом 5 кадров надежно отсекает внутрисловные смычки глухих согласных
  (30–100 мс), срабатывая только на реальные межрепликовые паузы от ~140 мс.
* Убран искусственный потолок резов на реплику: в длинных ASR-окнах (до 20 с)
  хвосты больше не остаются неразрезанными; длина любого сегмента гарантированно
  составляет от 0.6 до 6.6 с.
* Унифицирован формат времени `updated_at` в `voiceprints.json v3` на канонический
  RFC3339 (P1, P9) с прозрачной поддержкой чтения legacy Unix epoch чисел.
* Добавлены автотесты на паритет окон 0.6 с в ERes2NetV2 и дискриминацию пауз.

## [0.1.3] - 2026-10-28

### Исправлено

* Диаризация моно-записей: речь режется по тихим паузам на куски 1.5-6 с, и
  голос определяется по каждому куску, а не по 20-секундному окну ASR.
  Разговор двух людей в одном канале больше не схлопывается в одного
  спикера и один блок на всю запись.
* Моно: мелкие шумные кластеры приклеиваются к ближайшему голосу, а метки
  сглаживаются по времени - одиночный кусок не переключает спикера.
* Текст на стыках перекрывающихся ASR-кусков больше не теряется.
* Стерео-диаризация не изменялась: метки и тайминги совпадают с 0.1.1.

## [0.1.1] - 2026-10-27

### Добавлено

* macOS: живой захват микрофона через CoreAudio HAL (AudioUnit) без внешних
  процессов. Системный звук - через уже установленный
  BlackHole/Loopback/Soundflower: он опознаётся как отдельный вход и пишется во
  второй канал; без него запись идёт моно, а UI не предлагает два канала и не
  показывает шкалу собеседников.
* macOS: `NSMicrophoneUsageDescription` в Info.plist (и в секции `__TEXT`
  бинарника для запуска через `run.command`), иначе TCC блокирует микрофон.
* macOS: подпись и нотаризация в CI включаются секретами `APPLE_*`; без них в
  README описано снятие карантина `xattr -dr com.apple.quarantine`.

### Исправлено

* macOS: доступная память считается по `vm_statistics64` (free + inactive +
  speculative), а не по `_SC_AVPHYS_PAGES`; длинные записи больше не
  отказываются из-за заниженной оценки.
* Диаризация длинных записей: число окон разделения голоса ограничено 8 на
  реплику (было до 37 на 20-секундную реплику), разделяются только реплики
  длиннее 8 с, добавлен прогресс на шаге «Ищу смену голоса». Время расшифровки
  трёхминутной стереозаписи на x86 сократилось с ~22 до ~15 с, а 70-минутная
  запись проходит все этапы за ~7.5 мин вместо долгой остановки на 80%.
* macOS: `run.command` предупреждает, если бинарник собран под x86_64 и
  работает через Rosetta: на Apple Silicon это замедляет ONNX в разы.
* GigaAM: декодер и joint запускаются в один поток - на крошечных матрицах
  синхронизация пула потоков дороже самих вычислений.

## [0.1.0] - 2026-10-26

Первый публичный релиз.

### Добавлено

* Запись встреч с раздельными каналами микрофона и системного звука на Linux.
* Локальная расшифровка: GigaAM-v3 e2e RNNT int8 (русский) и Whisper large-v3-turbo int8.
* Диаризация и голосовые отпечатки ERes2NetV2 192-dim.
* Голосовые пакеты (`.voicepack.zip` / `.voicepack.json`) и база знаний из Markdown.
* Tauri-окно, трей, глобальный хоткей, автозапуск.
* Импорт и расшифровка готовых аудио/видеофайлов.
* Онбординг с очередью загрузки базовых моделей (~300 МБ).
* Проверка обновлений: при запуске приложение сверяет версию с последним
  GitHub Release и предлагает скачать новую; ручная проверка - в настройках.
* Android-сборка (экспериментальная), см. `ANDROID.md`.

### Изменено

* Убрана интеграция Markdown-базы знаний (`knowledge_dirs`); голосовые пакеты
  остаются основным способом вести список участников.
* Поддержка проекта переехала из главного экрана в левый нижний угол настроек.
* Удаление записи - иконка корзины справа вверху карточки и модальное
  подтверждение; внешние файлы убираются из списка без удаления с диска.
* На Android вкладки настроек больше не прокручиваются; скрыто поле микрофона
  в статусе «Определение»; видео и извлечение MP3 отключены.
* Справка больше не показывает блок «Локальные модели ИИ», когда базовые
  модели уже установлены.
* Прогресс расшифровки на телефоне: процент и полоса видны на главном экране,
  на странице текста карточка прогресса закреплена сверху.
* Диаризация: голос, попавший в микрофон и систему, объединяется в одну карточку;
  эхо-дубли реплик удаляются, имена идут по порядку («Участник 1», а не с 2).
* Фрагменты спикеров из stereo WAV проигрываются из выбранного канала (моно),
  без эха второго канала.

### Исправлено

* Windows: лишнее окно консоли при запуске из Проводника теперь скрывается;
  окно приложения открывается по ширине контента (920×860 вместо 1280×860).
* Windows: кнопка доната открывает ссылку в системном браузере, а не в
  заблокированном новом окне WebView2.
* Расшифровка тихой короткой речи: отсекается AAC priming, VAD видит тихие
  реплики, короткие тихие фрагменты склеиваются перед ASR, для тихих сегментов
  включается штраф на blank. Проверено на записи с тихими короткими репликами.
* Релиз публикует один пакет на платформу: Windows `.exe`, macOS `.dmg`,
  Linux `.AppImage` + `SHA256SUMS` (вместо 21 ассета).
* Галлюцинации ASR на тишине и шуме: штраф на blank включается только для
  короткой тихой речи, зацикленный вывод декодера отбрасывается. Проверено на
  записи, где раньше появлялось «и-и-и-и…».
* Android: запись больше не превращается в часы тишины при погасшем экране -
  добавлен foreground service `microphone` с wake lock и уведомлением.
* Android: расшифровка продолжается в foreground service `dataSync`; VAD
  пропускает окна цифровой тишины и показывает прогресс, а не висит на 5%.
* Android пишет моно (`mix`) - без второго канала из нулей; файл и VAD
  вдвое меньше. Настройки на телефоне больше не предлагают split.
* Нельзя запустить расшифровку во время записи (раньше это могло переключать
  тип foreground service и глушить микрофон).
* Голосовые отпечатки: сохраняются прототипы (до 10), проверяется размерность
  и embedding-space, удалённый голос снимает флаг «узнан» в открытой расшифровке.
* Счётчики реплик/секунд спикеров пересчитываются после объединения и
  дедупликации; статистика `speech_sec` больше не превышает длительность записи.
* Склейка тихих фрагментов не выходит за 12 секунд; `max_speakers=1` соблюдается.
* Долгая расшифровка длинных записей: спектр кадра считается смешанным БПФ
  вместо наивного O(n²)-ДПФ (~20× быстрее, без новых зависимостей); на шаге
  разделения голосов виден прогресс, SSE-события доходят до UI сразу - буфер
  сбрасывается после каждого пакета, а не по заполнении.
* Память на длинных записях: каналы раскладываются без копий, эхо-подавление
  удалено (резало микрофон и давало мало пользы - дубли реплик и так
  схлопываются по тексту и каналу). Пик памяти на стереозаписи упал примерно
  вдвое.
* Предел длительности считается по доступной памяти, а не по часам: до
  декодирования приложение оценивает пиковый расход (сэмплы + модели) и
  отказывает, только если памяти реально не хватает. Длительность и каналы
  берутся из заголовка WAV или из `ffprobe`.

### Известные ограничения

* Живой захват системного звука на macOS и Windows пока в разработке.
* Android: только микрофон, расшифровка экспериментальная.
* Релизные бинарники не подписаны; macOS Gatekeeper и Windows SmartScreen
  могут показать предупреждение.
* Linux-бинарники собраны на Ubuntu 24.04 (glibc 2.38+), macOS - Apple Silicon
  и 13.4+: этого требует предсобранный ONNX Runtime.
