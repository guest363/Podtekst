# Meeting Recorder - Доменный контекст (CONTEXT.md)

Единый понятийный аппарат и доменный язык проекта Meeting Recorder (Запись встреч).
Предотвращает терминологические расхождения и галлюцинации в коде, UI и документации.

## 1. Базовые доменные термины

**Audio Channel (Канал аудио):**
Один из физических потоков внутри стереодорожки 16 кГц:
- **Left (Левый канал):** локальный микрофон пользователя (`mic`).
- **Right (Правый канал):** системный звук звонка или собеседников (`sys`), полученный через loopback (PipeWire / CoreAudio BlackHole / WASAPI).
- **Mono / Mix:** одноканальная запись (микрофон на смартфонах или моно-совещания).
_Не использовать_: Track (трек), Stream (в значении канала), Source (источник).

**Turn (Реплика):**
Законченное смысловое высказывание одного участника с временными границами `start_ms` и `end_ms`, текстом и меткой спикера.
_Не использовать_: Utterance (высказывание), Sentence (предложение), Message (сообщение), Bubble (бабл).

**Voiceprint (Голосовой отпечаток):**
192-мерный нормализованный вектор признаков голоса (L2-норма), сформированный нейросетью ERes2NetV2 из аудиофрагмента (в core-кластеризации от 0.6 с, для эталонов профилей от 1.5 с).
_Не использовать_: Voice profile (профиль голоса), Voice ID, Signature (сигнатура).

**Person (Участник / контакт):**
Именованный контакт из базы `people.json`, которому сопоставлен один или несколько эталонных голосовых отпечатков.
_Не использовать_: User (пользователь), Contact (контакт), Account (аккаунт).

**Speaker Label (Метка спикера):**
Идентификатор говорящего в расшифровке: либо распознанный `Person` по имени, либо нераспознанный кластер диаризации (например, `SPEAKER_01`).
_Не использовать_: Author (автор), Role (роль).

**Voice Pack (Голосовой пакет):**
Экспортируемый независимый набор профилей участников и сэмплов голоса (`.voicepack.zip` или папка с `people.json`, `voiceprints.json` v3 и `snippets/*.wav`).
_Не использовать_: Dataset (датасет), Voice model (голосовая модель).

**VAD Window (Окно детектора активности речи):**
Минимальный фрейм аудио 16 кГц (512 сэмплов / 32 мс), подаваемый в Silero VAD для определения наличия человеческого голоса.
_Не использовать_: Slice, Fragment.

**ASR Chunk (Окно распознавания речи):**
Фрагмент непрерывной речи, выделенный детектором VAD (до 20 секунд), передаваемый в акустическую модель GigaAM или Whisper.
_Не использовать_: Batch, Segment.

**Diarization Chunk (Фрагмент диаризации):**
Пост-ASR фрагмент речи для вычисления эмбеддинга спикера. В моно реплика делится по естественным паузам на фрагменты от 0.6 до 6 секунд (до 6.6 с при отсутствии пауз); в стерео канал сразу разделяет спикеров. Размеченные фрагменты образуют интервальное дерево: каждому слову исходной ASR-реплики назначается спикер с наибольшей площадью пересечения, а итоговая реплика делится на стыке смены спикеров. Поскольку ASR пока не выдаёт пословные таймстемпы, границы слов интерполируются внутри реплики.
_Не использовать_: Slice, Piece.

## 2. Архитектура и стадии конвейера обработки

Любая запись проходит строгие последовательные фазы:
1. **Захват (Capture):** раздельная запись в левый (микрофон) и правый (система) каналы с частотой 16 кГц.
2. **VAD (Voice Activity Detection):** нарезка дорожек на речевые фрагменты нейросетью Silero VAD v6.2 с pre-roll 64 мс; длинные ASR-окна делятся по минимуму вероятности речи во второй половине окна.
3. **ASR (Automated Speech Recognition):** локальное распознавание текста (GigaAM RNNT для русского, Whisper Turbo для остальных языков).
4. **Diarization & Embedding:** извлечение 192-мерных векторов моделью ERes2NetV2 3D-Speaker по паузам реплик.
5. **Clustering & Matching:** complete linkage O(n²), силуэт-оценка фрагментов и спикеров, пословная атрибуция через интервальное дерево и сопоставление с эталонами через венгерский алгоритм.
6. **Artifact Generation:** атомарная запись файлов протокола (`.md`), чистого текста (`.txt`) и разметки (`.transcript.json`).

## 3. Соответствие сущностей UI ↔ Код (Rust) ↔ Файлы на диске

| Концепция в UI | Тип / Модуль в Rust | Файл / Хранилище на диске | Пояснение |
|---|---|---|---|
| Запись в списке | `mr_app::media_registry::MediaItem` | `<storage>/<name>.wav` | Записанный или импортированный аудиофайл |
| Протокол со спикерами | `mr_app::transcribe::Transcript` | `<storage>/<name>.md` | Markdown с таймкодами и именами |
| Текст для нейросетей | `String` (чистый текст) | `<storage>/<name>.txt` | Текст без разметки для отправки в LLM |
| Структура расшифровки | `mr_app::transcribe::TranscriptJson` | `<storage>/<name>.transcript.json` | JSON с таймкодами, словами, эмбеддингами и additive-полями `silhouette` у реплик и спикеров |
| Каталог участников | `mr_packs::PeopleManifest` | `<app_data>/packs/<id>/people.json` | Список участников и привязка к сэмплам |
| База голосовых векторов | `mr_packs::VoiceprintsV3` | `<app_data>/packs/<id>/voiceprints.json` | 192-мерные векторы (версия формата v3) |
| Каталог ИИ-моделей | `mr_models::Manifest` | `models-manifest.json` в коде | Официальные ссылки, SHA-256 и размеры |
| Скачанные веса моделей | `PathBuf` к ONNX-файлам | `<app_data>/models/<id>/` | Папка с проверенными `.onnx` файлами |
| Настройки приложения | `mr_app::config::AppConfig` | `<app_data>/config.json` | Выбранные устройства, пороги и язык |

## 4. Отрицательные ограничения и Zero-Leak

- **Запрет на реальные имена файлов и людей:** запрещено указывать личные данные в PR, issue, логах, тестах и коммитах. Все сценарии описываются строго через технические параметры: *«моно, 5 мин, 2 спикера»*.
- **Разделение стерео и моно:** алгоритмы диаризации различаются. В стерео канал сразу определяет говорящего (микрофон или система). В моно речь делится по естественным паузам на окна (0.6-6 с) с вычислением вектора для каждого фрагмента.
- **Обратная совместимость форматов:** структура `voiceprints.json v3` и `.transcript.json` является публичным контрактом. Существующие поля нельзя удалять или менять без миграции (P9); новые выходные поля добавляются только аддитивно, чтобы старые файлы и клиенты продолжали читаться.
