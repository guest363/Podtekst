# Регламент работы с ИИ (Workflow)

Руководство по взаимодействию и разработке с помощью ИИ-агентов в проекте Meeting Recorder.

## 1. Два трека задач

### Track 1: Стандартные задачи (По умолчанию)
Применяется для: исправлений ошибок, точечных доработок UI, добавления тестов, рефакторинга без изменения существующих контрактов.

1. **Минимальный рабочий diff:** берите самое простое решение, которое полностью закрывает задачу (принцип Ponytail).
2. **Чинить первопричину (Root Cause):** исправляйте ошибку на том базовом слое, где она возникает. Не маскируйте её в вызывающем коде или интерфейсе (P10).
3. **Локальная верификация:** перед завершением хода обязательно выполните команды из чек-листа верификации.

### Track 2: Архитектурные и критические изменения
Применяется при:
- Изменении схемы сохранения данных (`voiceprints.json v3`, `.transcript.json`).
- Изменении контракта HTTP REST API или IPC между Rust и Web UI.
- Добавлении новых нейросетевых моделей или замене аудиодвижка.
- Изменении флагов запуска CLI или переменных окружения (P9).

**Порядок действий Track 2:**
1. **Согласование перед кодом:** кратко опишите цель, сравните 2 варианта реализации и опишите влияние на обратную совместимость.
2. **Human Approval:** приступайте к редактированию кода строго после одобрения человеком.
3. **Обновление документации:** синхронно обновите `CONTEXT.md` и локальные `AGENTS.md` затронутых крейтов.

## 2. Чек-лист верификации

Задача считается завершённой только после успешного прогона проверок:

```bash
# 1. Линтер Rust ядра (строгий режим без предупреждений)
cargo clippy --workspace --all-targets --locked --manifest-path src-tauri/Cargo.toml -- -D warnings

# 2. Математические и интеграционные тесты
cargo test --workspace --locked --manifest-path src-tauri/Cargo.toml

# 3. Проверка нативной оболочки Tauri (если изменялись mr-app или интерфейс)
cargo clippy -p mr-app --features tauri-ui --all-targets --locked --manifest-path src-tauri/Cargo.toml -- -D warnings

# 4. Проверка типов и сборка фронтенда (если изменялся ui/web/frontend)
cd ui/web/frontend && yarn check && yarn build
```

## 3. Протокол безопасности данных (Zero-Leak)

Перед созданием коммита, PR или отчёта убедитесь:
- В `git status` и `git diff` нет файлов с личными данными (`people.json`, `voiceprints.json`, `config.json`, реальных `.wav` записей).
- В текстах коммитов и описании PR нет имён людей, тем бесед и реальных названий файлов.
- Указывайте только обезличенные параметры записи по правилу P12.
