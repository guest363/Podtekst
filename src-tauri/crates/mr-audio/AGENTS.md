# mr-audio - AGENTS.md

Крейт низкоуровневого захвата аудио, потокового ресемплинга и декодирования форматов.

## 1. Архитектура и строгие инварианты

- **Динамическая загрузка (Zero System Dependencies):** библиотеки `libpulse` на Linux и `libaaudio` на Android подключаются динамически через `dlopen`. Не добавлять статических ссылок на C-библиотеки в `Cargo.toml`. При отсутствии библиотеки в системе код возвращает понятную ошибку без падения процесса.
- **Разделение каналов:** в стереорежиме микрофон всегда пишется в левый канал (`mic`), системный звук собеседников - в правый (`sys`). Разделение полезно только в наушниках: при выводе на колонки микрофон слышит собеседников, и `mr-app` на ранней стадии сворачивает дублирующиеся каналы в один микрофонный. При моно-записи используется один канал без пустых заполнителей.
- **Целевой формат:** все потоки ресемплируются в **16 000 Гц PCM** перед записью и передачей в конвейер транскрибации.
- **Декодирование файлов:** библиотека Symphonia является основным нативным декодером (`MP3`, `WAV`, `M4A`, `OGG`, `Opus`, `FLAC`). Внешний процесс `ffmpeg` вызывается строго как запасной вариант для видеоконтейнеров (`MKV`, `WebM`, `MOV`, `AVI`).

## 2. Ключевые файлы

- `src/lib.rs` - фасад крейта, сплиттер каналов, потоковый ресемплер и расчёт уровней громкости (RMS).
- `src/decode.rs` - нативное декодирование через Symphonia и проверка метаданных медиа.
- `src/capture/mod.rs` - абстракция аудиоустройств и единый интерфейс захвата.
- `src/capture/linux.rs` и `src/capture/pulse.rs` - захват звука в Linux через PipeWire и PulseAudio с динамической загрузкой `libpulse.so.0`.
- `src/capture/macos/` - CoreAudio HAL через AudioUnit (микрофон, BlackHole и другие loopback-входы) и системный звук через ScreenCaptureKit (`sck.rs`, разрешение проверяет `permission.rs`).
- `src/capture/android.rs` - захват аудиопотока в Android через `libaaudio.so`.
- `src/capture/windows.rs` - нативный захват WASAPI (shared mode): микрофон и loopback системного звука, без внешних утилит; через крейт `windows` (уже в графе через Tauri).
- `src/echo/` - замер задержки эха живых стерео-записей (GCC-PHAT). Подавления звука (AEC) в коде нет: оно удалено после двух неудачных попыток. Оценка задержки используется в `mr-app` только как VAD-гейт пролезания системного канала в микрофон.

## 3. Состояние и известные ограничения

- **Linux PipeWire monitor:** системный звук пишется через мониторный источник текущего устройства вывода (`.monitor`).
- **macOS системный звук:** по умолчанию через ScreenCaptureKit (псевдоустройство `sck`), без виртуального драйвера; нужен доступ к записи экрана и системного аудио. BlackHole/Loopback остаётся запасным выбором и виден как обычный вход.
- **Windows Loopback:** WASAPI loopback отдаёт пакеты только во время воспроизведения — дорожка системного звука добирается тишиной по таймеру, чтобы совпадать с микрофоном по времени.
- **Подавление эха:** AEC удалено после двух неудачных попыток: на живых записях фильтр давал ERLE~0 при двузначных дБ на синтетике - подгонка порогов под конкретную комнату, а не робастное решение. Дубли эха между каналами давятся на текстовом уровне (`dedupe_cross_channel` в `mr-app`), а пролезание системного канала в микрофон отсекается VAD-гейтом по задержке (`channel_mix::suppress_mic_bleed`), без фильтрации звука.

```bash
# Тесты ресемплинга, декодера и сплиттера каналов

cargo clippy -p mr-audio --all-targets --locked -- -D warnings
```
