# Метрики речи - спецификация v1

Статус: черновик, 2026-11-14.
Все исследования (конкуренты, методы и валидация, нормы по форматам) хранятся в Obsidian,
проект «Подтекст», папка «Исследования». В репозитории - только эта спецификация
и `VERIFICATION.md`.
Предмет: локальный слой измеримых метрик речи вместо распознавания эмоций.

---

## 1. Решение

Распознавание эмоций на реплику из плана убрано. Причины зафиксированы в `ROADMAP.md` («Не в планах»):
нет эталона, на дальнем поле модель схлопывается в «нейтрально», AI Act ст. 5(1)(f) запрещает
infer emotions на рабочем месте и в образовании.

Вместо ярлыка считаются наблюдаемые свойства речи. Метрика отличается от интерпретации тем, что
для неё можно написать формулу и протокол проверки:

- **метрика** - «монолог 4:10», «доля речи 47 %», «медиана паузы перед ответом 180 мс»;
- **интерпретация** - «доминировал», «был неуверен», «низкая эмпатия». В артефакт не попадает,
  в UI допускается только как объяснение диапазона, без оценки человека.

Три принципа:

1. **Описываем встречу, а не человека.** Никаких рейтингов, лидербордов и композитных индексов.
2. **Абсолютные значения скрыты.** F0 и энергия сравниваются только с собой (перцентиль внутри
   встречи или личная базовая линия), потому что зависят от анатомии, микрофона и AGC.
3. **Качество записи - входной фильтр.** Просодия не показывается, если SNR плохой: иначе шум
   микрофона будет выглядеть свойством говорящего.

## 2. MVP: шесть метрик и одно отличие

Канон, который рынок уже понимает (Gong, Avoma, Grain, Jiminny, Fireflies):

| # | Метрика | Формула | Ед. |
|---|---|---|---|
| 1 | Доля речи | `Σ(b_i−a_i)` спикера / `Σ` всех реплик; отдельно доля от длительности записи | % |
| 2 | Самый длинный монолог | склейка реплик одного спикера при зазоре < 1.5 с; медиана, p90, максимум | с |
| 3 | Смены говорящего | число переходов между спикерами на минуту речи | 1/мин |
| 4 | Пауза перед ответом | `a_j − b_i` на переходах разных спикеров, `0..3 с`; медиана, p90, `n` | мс |
| 5 | Темп речи | `words / (b_i−a_i) · 60`; при наличии word timing - без пауз | слов/мин |
| 6 | Тишина и паузы | промежутки в речи ≥ 5 с: число, доля, максимум; доля пауз в реплике | с, % |

Отличие, которого нет ни у одного проверенного конкурента: **перекрытия и перехваты**. Считаются
для stereo-записей по пересечению интервалов разных каналов и по кадрам PyAnnote; для mono -
только приближение по разрывам, с явной пометкой точности.

Второе отличие - **навигация**, а не дашборд: «перейти к самому длинному монологу», «показать все
паузы > 5 с», «показать первый перехват», «проиграть только этого спикера».

Третье - **локальность**. Все конкуренты облачные; у нас расчёт идёт на устройстве и это видно в UI.

## 3. Чего не делаем

- Эмоции, arousal, валентность, стресс, усталость, «вовлечённость», «лидерство», «эмпатия».
- Композитный индекс «качество коммуникации» одним числом: его нельзя защитить.
- Рейтинг участников и сравнение с командой. Сравнение - только с собой и с типом встречи.
- Абсолютную громкость как свойство человека.
- Jitter/shimmer/HNR в UI без калиброванного микрофона и устойчивого гласного.
- Запись метрик в `.transcript.json`: схема не меняется [P9], метрики - отдельный артефакт.

## 4. Конкурентная рамка

Что взять: канон из шести метрик, диапазоны вместо score, разбивку по каждому участнику (у Gong -
только владелец звонка, у Chorus/Fathom/Salesloft - по репам), экспорт CSV/JSON.

Где мы выигрываем:

1. Перекрытия и перехваты - в публичной документации конкурентов отсутствуют.
2. Навигация по метрикам записи - нет ни у кого.
3. Офлайн-расчёт без аккаунта и загрузки аудио - архитектурный, а не маркетинговый дифференциатор.
4. Записи живой комнаты: конкуренты захватывают онлайн-встречи ботом или расширением.
5. Нормы по типу встречи: у всех бенчмарки sales-ориентированные (43:57 у Gong, 40-60 % у Avoma,
   «выигранные сделки» у Jiminny); норм для лекции, психологической сессии или скрама нет.
6. Личная базовая линия вместо командного рейтинга - и она у нас уже есть в виде голосовых отпечатков.

Чего избегать: копировать цветовые пороги green/red и лидерборды Avoma/Jiminny. Это превращает
описание встречи в оценку сотрудника, ровно на той границе, где начинается AI Act.

## 5. Архитектура

### 5.1. Слои

| Слой | Вход | Метрики | Тир |
|---|---|---|---|
| L0 Качество записи | WAV | клиппинг, SNR, полоса, дисбаланс каналов, эхо-прокси | A |
| L1 Взаимодействие | таймкоды + диаризация | доля речи, монологи, перехваты, латентность, паузы | A |
| L2 Просодия | WAV + сегменты | F0, энергия, темп артикуляции, паузы | B |
| L3 Качество голоса | чистый сигнал | jitter, shimmer, HNR | B, только с калибровкой |

L0 считается всегда и первым. При `grade != good` поля L2/L3 остаются `null`, а в UI появляется
причина, а не серое число.

### 5.2. Крейт

Реализован: `mr-metrics`, чистый крейт без `ort`, файлового ввода-вывода при расчёте
взаимодействия и без сети. Компилируется на Android и в headless-сборке.

Почему не внутри `mr-app`: модуль `transcribe` целиком под `#[cfg(feature = "onnx")]`
(`mr-app/src/lib.rs` L26-27), а метрики должны работать в headless/Android-сборке без ONNX.
Почему не внутри `mr-summarize`: это домен итогов; метрики нужны и без саммари (на Android
summary отдаёт 501).

Зависимости: `mr-audio` для декодирования и FFT. Новых внешних крейтов не требуется:
radix-2 FFT уже есть в `mr-audio/src/echo/fft.rs` L35-75 (открыт как `mr_audio::echo::fft`),
RMS и AGC - в `mr-audio/src/dsp.rs` L59-181.
`rustfft`/`realfft` не добавляем [P2].

### 5.3. Tier A

Вход - только реплики: `start`, `end`, `speaker`, `channel`, `text`, опционально `words`.
Аудио не читается, кроме шага L0.

Что уже есть в коде:

- `unique_speech_sec` - union интервалов, `transcribe/document.rs` L149-171; в API не отдаётся.
- `monologue_ratio`, `short_turn_ratio`, `question_ratio`, `chars_per_utt` -
  `mr-summarize/src/classify.rs` L305-359; функция приватная, в JSON не попадает.
- `total_speech_sec` по спикеру - `transcribe/mod.rs` L65-81, в UI не выводится.

Правило: `share_s` считается по union интервалов спикера, а не суммой длительностей - иначе
перекрытия дают больше 100 %.

### 5.4. Tier B

Потоковая обработка блоками 10 с, кадр 25 мс / шаг 10 мс. F0 - YIN (CMNDF, порог 0.1,
параболическая интерполяция), сравнение в полутонах `st = 12·log2(f/27.5)`.
Память: минута 16 кГц моно - 3.8 МБ `f32`; файл целиком не нужен.

Чтение аудио: `decode_wav_range_16k(path, start, end, Some(channel))`,
`mr-audio/src/decode.rs` L143-196 - по репликам, без загрузки гигабайтного WAV.

### 5.5. Артефакт и кэш

Схема `.metrics.json` описана в заметке «Метрики речи - методы и валидация» (Obsidian).
В v1 файл не пишется: ответ API и есть контракт.

Правила:

- По умолчанию файл **не пишется**: метрики считаются на лету и кэшируются в памяти.
- Кэш: `path + len + mtime + source_rev` по образцу `summary/cache.rs` L25-72. `source_rev`
  не учитывает `words`/`ctc_used`, поэтому для метрик с word timing нужен ещё mtime.
- Если файл всё же пишется (экспорт, пакетная обработка) - добавить суффикс в `SIDECAR_SUFFIXES`
  (`http/files.rs` L11-17), иначе rename/delete оставит сироту.
- Персональные метрики писать только `write_atomic_private` [P12].

## 7. Нормализация и подача

1. Основное число для спикера - **перцентиль внутри встречи**: «больше, чем у остальных здесь»,
   а не «много по мировым нормам».
2. Для повторных встреч - отклонение от личной базовой линии в полутонах и дБ. Условие:
   ≥ 5 встреч, ≥ 120 с чистой речи, ≥ 3 устройства; иначе `baseline.available = false`.
3. Абсолютные значения - только в экспертной карточке, с единицами и пометкой о зависимости
   от микрофона.
4. Формулировки: «темп 152 слова/мин, выше вашего обычного на 18» вместо «говорил быстро»;
   «пауза перед ответом 40 мс» вместо «перебивал».
5. Каждое число сопровождается `confidence` и, при необходимости, `warnings`
   (`low_snr`, `agc`, `heavy_overlap`, `echo_suspected`, `few_turns`).

## 8. Пресеты и нормы

Открытых норм для рабочих совещаний 2-6 человек нет: ни по доле речи, ни по длине монолога,
ни по паузам, ни по перехватам. Подтверждённые числа есть только для продаж (Gong, Jiminny)
и психотерапии (CUEMPATHY), и они не переносятся на русскую спонтанную речь в переговорке.
Разбор источников и пробелов - в Obsidian, заметка «Метрики речи - нормы по форматам».

Поэтому нормы по пресетам **не задаются**, и green/red порогов в UI нет. Показываем:

- долю речи как факт, без оценки «много/мало»;
- сравнение только с личной базовой линией;
- никаких рейтингов и «хорошо/плохо».

Если наберётся 10-20 записей одного формата, диапазоны можно вывести из них - но это будет
внутренняя норма проекта, а не отраслевая, и её придётся явно так называть.

## 9. Валидация

Эталон объективной метрики - сам сигнал с известными свойствами. Проверяем воспроизводимость,
а не «правильность эмоции». Полный протокол - в Obsidian, заметка
«Метрики речи - методы и валидация».

Обязательный минимум перед показом пользователю:

| Проверка | Критерий |
|---|---|
| Синтетика: синус 100 Гц, ступень −20→−10 dBFS, клики 5 Гц, тишина | F0 ±1 Гц, ΔRMS ±0.1 дБ, клиппинг ±0.01 % |
| Сверка с Praat/openSMILE на одном WAV | F0-медиана 1 %, F0-IQR 10 %, HNR 1 дБ |
| Тест-ретест | побайтово одинаковый JSON |
| Смена устройства: 5 дикторов, 3 микрофона | ICC ≥ 0.75, CV ≤ 10 % |
| Ручная разметка 200 реплик | κ ≥ 0.8 по спикеру, границы ±100 мс |
| Регрессионный корпус 10-20 обезличенных записей | выход за допуск - блокирующий дефект |

Допуски по метрикам: доля речи ±2 п.п., перекрытие ±2 п.п., латентность ±50 мс,
длина реплики ±100 мс, темп ±0.3 слога/с.

DoD: метрики видны на существующей записи, пересчёт после редактирования транскрипта.

**M5. Просодия (1-2 недели).** Статус: реализовано (YIN, энергия, темп, паузы);
сверка с Praat на живом корпусе ещё не проведена.

DoD: сверка с Praat в допуске, тест-ретест нулевой.

**M6. Личная базовая линия (после 5 встреч у пользователя).** Статус: готово
(`mr-app/src/metrics.rs`, `<app_data>/metrics-baseline.json`, 0600).
Отклонение в полутонах и дБ по голосовым отпечаткам.

## 11. Риски

1. **Эхо между каналами** даёт ложные 100 % перекрытия. До L1 проверять дубли каналов
   (корреляция огибающих, текстовый dedupe); при доле дублей > 20 % перекрытия помечаются
   `confidence: low`.
2. **Mono и импорт видео** - перекрытий нет, `channel=None`. Показывать «недоступно», а не ноль.
3. **Android**: всегда mono, нет summary и `ffmpeg`. Метрики не прятать под `summaryAvailable`;
   L2 считать на устройстве, но без внешних процессов.
4. **AGC и кодек** ломают энергию и HNR. Флаг `agc_suspected`, сравнение только внутри спикера.
5. **Правки транскрипта** меняют метрики: редактирование очищает `words` и `ctc_used`
   (`transcript_edit.rs` L180-186). Кэш обязан учитывать mtime.
6. **P8**: `diarize.rs` - 4660 строк; метрики туда не добавлять. Только отдельный крейт/модуль.
7. **P12**: метрики по спикерам - персональные данные. Не логировать имена и текст в dev-артефактах,
   в тестах - только синтетика.

## 12. Юридическая граница

Метрики темпа, пауз и долей не являются inference эмоций и под запрет ст. 5(1)(f) сами по себе
не попадают. Граница проходит по подаче и использованию:

- допустимо: «монолог 4:10», «пауза 5 с», «доля речи 47 %»;
- недопустимо: «низкая эмпатия», «неуверенный тон», «стресс», «оценка кандидата».

Правила: не строить рейтинг сотрудников, не использовать в кадровых решениях, не выводить
интерпретацию без числа. Перед релизом в ЕС - отдельная правовая проверка формулировок UI.

## 13. Открытые решения

1. **Крейт**: решено - новый `mr-metrics`.
2. **Артефакт**: решено - считать на лету, кэш в памяти; `.metrics.json` не пишется.
3. **Перекрытия**: реализовано приближение по каналам; точный прогон PyAnnote - по требованию.
4. **Нормы**: не задаются - открытых норм для рабочих совещаний нет (заметка в Obsidian);
   показываем только распределение внутри встречи и личную базовую линию.
5. **Экспорт**: CSV и JSON не сделаны.
