# Совместимость голосовых профилей при исправлении масштаба fbank

Проверка сравнивает прежний frontend ERes2NetV2 (`log_mel_frames` на нормализованном аудио, затем CMN) и исправленный frontend (фиксированное умножение на 32768 перед той же процедурой). Модель, размерность 192, L2-нормализация и пороги не менялись. Проверяется влияние только frontend: адаптивная регулировка усиления в этот эксперимент не включена.

## Метод

Использованы только уже загруженные открытые VoxConverse и AMI: 22 локальные метки спикеров из 7 записей. Метки действуют внутри записи; отрицательные пары строятся только между разными спикерами одной записи, чтобы повторяющийся диктор в разных файлах не стал ложной отрицательной парой.

По RTTM исключены интервалы остальных спикеров; с краёв чистых интервалов убрано по 150 мс. На спикера выбраны четыре непересекающихся окна по 3 с: три для центроида профиля и одно отложенное для запроса. Для каждой длины 0,8 / 1,5 / 3 с используются начала этих окон. Профили строятся при исходном уровне; запросы — при 0 / −18 / −36 dB. Ослабление выполняется в float без дополнительного квантования и клиппинга.

Всего 88 исходных окон, 792 вычисления эмбеддингов, батчи до 8 без дополнения нулями. Профиль — L2-нормализованная сумма трёх единичных векторов одинаковой длины. Проверяются три режима: **O/O** — старый профиль и старый запрос; **N/N** — новый профиль и новый запрос; **O/N** — старый профиль и новый запрос. В каждом режиме и условии 22 положительных запроса и 54 направленные отрицательные пары.

Фиксированные условия: cosine ≥ **0,45**, отрыв от следующего кандидата ≥ **0,015**. FN означает положительную пару ниже 0,45; FP — отрицательную пару не ниже 0,45, независимо от отрыва. Отдельно считается ошибочно принятая личность с учётом обоих условий. Пороговое FP не равно ошибке назначения имени.

## Ограничения вывода

На этой выборке старый профиль с новым frontend не ухудшил агрегаты решений относительно полностью нового профиля. Это не общая гарантия совместимости: 22 метки и 54 отрицательные пары на условие не покрывают произвольные микрофоны, языки, очень тихие спектрально разреженные сигналы и большие каталоги профилей. Повторные условия используют те же окна, поэтому их нельзя считать независимыми испытаниями.

При 0,8 с остаётся 6 FN из 22; при 3 с остаётся 16 пороговых FP из 54 и одно ошибочное принятие личности. Эти ошибки присутствуют и в прежнем режиме. Эксперимент не обосновывает изменение порогов и не заменяет полную проверку назначения имён в приложении. Личные профили не читались, миграция или перезапись данных не выполнялась.

## Воспроизведение

Временный Cargo-helper находится вне репозитория в `$BENCH_ROOT/runs/level-fix/profile-compat`; его исходники и локальный результат нужно сохранять вместе. Он зависит от текущего `mr-ml` через локальный Cargo path и использует `OrtSession`. Старый путь в helper фиксирует вычисление `log_mel_frames(raw, ERES2NETV2_FRONTEND)` и вычитание среднего каждого mel-канала в f32; новый вызывает `eres2netv2_fbank`.

`prepare.py` читает локальные WAV/RTTM из `data/voxconverse` и `data/ami_ihm`, приводит аудио к моно 16 кГц через локальный FFmpeg и создаёт `inputs.json`. Запись входа имеет числовые `speaker`, `recording` и список `samples` из четырёх путей к 3-секундным little-endian f32-фрагментам: сначала три обучающих, затем отложенный. Корень локального набора в `prepare.py` и Cargo path зависимости задаются по своему окружению; сетевых загрузок нет.

```bash
COMPAT_DIR="$BENCH_ROOT/runs/level-fix/profile-compat"
python3 "$COMPAT_DIR/prepare.py"
cargo run --offline --release --manifest-path "$COMPAT_DIR/Cargo.toml" -- \
  "$COMPAT_DIR/inputs.json" "$ERES2NETV2_MODEL" "$COMPAT_DIR/metrics.json"
```

`ERES2NETV2_MODEL` указывает на локальный `eres2netv2_emb.onnx`. Результат `metrics.json` содержит только числовые агрегаты. Ни аудио, ни эмбеддинги не входят в этот отчёт или репозиторий. Helper не поставляется с приложением; без сохранённых исходников helper и исходного набора сам этот Markdown не является автономным бенчмарком.
