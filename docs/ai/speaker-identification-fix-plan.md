# План исправления определения участников

Дата: 11 ноября 2026. Ветка: `voice-fix-2`. Исследованный код: `131ba7d`.
Разбор исходного состояния и план для PR #84. Исправления реализованы; исходные ссылки ниже относятся к `131ba7d`.

Проверялось приложение и его внутренние Rust-модули, edition 2021, MSRV 1.92.
Основной риск находится в подготовке аудио и передаче происхождения каналов,
а не в загрузке модели голосовых отпечатков.

## Что установлено

### 1. Сведение каналов отключает защиты от загрязнения отпечатков — P1

Источники:

- `src-tauri/crates/mr-app/src/transcribe/pipeline.rs:215`: новое сведение
  микрофона и системы, добавленное в `131ba7d`.
- `src-tauri/crates/mr-app/src/transcribe/pipeline.rs:242`: исходные два канала
  заменяются одной дорожкой; затем `is_stereo` становится `false`.
- `src-tauri/crates/mr-app/src/transcribe/pipeline/vad.rs:114`: `EchoEvidence`
  передаётся дальше только в стереорежиме.
- `src-tauri/crates/mr-app/src/transcribe/diarize.rs:1455` и `:1496`: защита
  коротких ответов и ограничение назначения имён работают только при
  `echo.is_some()`.

После успешного сведения сведения об эхе не доходят до диаризации. При этом
в `fold_playback` микрофон полностью не исключается из кадров `DoubleTalk`
и `Uncertain`: их аудио складывается с системным. Следовательно, эмбеддинги
могут содержать оба голоса, а минимальный объём чистой речи для имени уже
не проверяется. Дополнительно включается моно-сглаживание меток.

Правила: [P10] исправление причины на базовом слое, [P5] сохранение смысла каналов.

Исправление для этого PR: вернуть исходные каналы в существующий стереоконвейер
с VAD-гейтом эха и дедупликацией. Цифровые дубли продолжать распознавать отдельно.
Проверку достаточности чистой речи перед назначением имени применять ко всем
режимам, независимо от наличия эха. Нельзя просто передать микрофонную маску
эха в общий микс: она начнёт исключать из него полезную системную речь.

### 2. В документ записывается индекс обработанного, а не исходного канала — P1

Источники:

- `src-tauri/crates/mr-app/src/transcribe/pipeline.rs:242` и `:341`: сведённая
  дорожка получает индекс `0`.
- `src-tauri/crates/mr-app/src/transcribe/pipeline/asr.rs:314`: этот индекс
  сохраняется в `Utterance.channel`.
- `src-tauri/crates/mr-app/src/transcribe/diarize.rs:234`: тот же канал попадает
  в образцы для карточки спикера.
- `src-tauri/crates/mr-app/src/http/people.rs:1083`: «запомнить голос» берёт
  канал из документа и передаёт его в извлечение отпечатка.
- `src-tauri/crates/mr-app/src/transcribe/models.rs:157`: извлечение читает
  этот канал исходного аудиофайла, а не обработанную дорожку.

После сведения реплика удалённого участника получает `channel=0`, а обучение
читает исходный микрофон. В выбранном интервале там может находиться эхо,
другой человек или тишина. Это создаёт риск загрязнения сохранённого профиля,
который затем влияет на следующие записи. Факт загрязнения пользовательских
профилей в этом исследовании не проверялся.

В двух локальных результатах со сведением все 114 и 98 итоговых реплик имели
`channel=0`, хотя исходные файлы были стерео. Аналогичный дефект возможен при
выборе правого канала цифрового дубля: `remove(pick)` с последующим
`enumerate()` также превращает исходный канал `1` в обработанный `0`.

Правила: [P1] единый смысл поля, [P9] совместимость формата, [P10] исправление
общего преобразования каналов.

Исправление: отдельно передавать внутренний индекс обработки и ссылку на
исходный канал. При построении документа и образцов использовать исходный
канал. Для настоящего микса не выдавать индекс микрофона за источник.
Просто заменить индекс на `None` недостаточно: и быстрый WAV-декодер
(`mr-audio/src/decode.rs:165`), и запасной путь извлечения выбирают первый
исходный канал. При невозможности доказать источник стереофрагмента
сохранение эталона должно завершаться существующей ошибкой 422 до записи
профиля. Настоящий монофайл с `channel=None` должен продолжать работать.
HTTP-обработчик остаётся адаптером; выбор и проверка аудио — в общем слое
извлечения. Новые публичные поля не требуются.

### 3. «Чистые секунды» считаются по полной длительности реплики — P1

Источники:

- `src-tauri/crates/mr-app/src/transcribe/diarize.rs:990`: после исключения
  перекрытий доступно число действительно использованных сэмплов.
- `src-tauri/crates/mr-app/src/transcribe/diarize.rs:1410`: в `durs` всё равно
  записывается полная длительность реплики.
- `src-tauri/crates/mr-app/src/transcribe/diarize.rs:696`: `eligible_clusters`
  суммирует именно `durs`, если у реплики вообще есть эмбеддинг.

Один короткий чистый участок внутри длинной реплики позволяет пройти порог
`MIN_NAMED_CLEAN_SEC = 2.0`. Отдельная проверка исходной функции это воспроизвела:
реплика 5 с с эмбеддингом из 0,8 с проходит при текущем аргументе `durs=[5.0]`
и не проходит при `durs=[0.8]`. Это синтетическая проверка учёта длительности,
а не замер точности на реальной записи.

Правила: [P1] единый смысл длительности, [P10] проверка на слое формирования
акустических фрагментов.

Исправление: хранить длительность реплики отдельно от покрытия чистым аудио.
Для допуска к имени считать объединение использованных чистых интервалов,
без повторного учёта перекрывающихся окон эмбеддингов. Центроиды взвешивать
по использованному аудио, а не по длине исходной реплики. Окончательное
назначение имени должно использовать этот же расчёт во всех режимах:

```rust
let eligible = eligible_clusters(&raw_clusters, &label_of, &embs, &clean_durs);
```

Здесь `clean_durs` — предлагаемая отдельная величина; такого массива в текущем
коде нет. Простая замена на сумму `AcoustUnit.dur` недостаточна: окна перекрываются.

### 4. Текущая приёмка допускает перестановку имён участников — P2

Источник: `src-tauri/crates/mr-app/tests/diar_local.rs:81`, `:230`, `:309`.
Локальный интеграционный тест отключён через `#[ignore]`; `probe_mark` только
печатается. DER оптимально переставляет метки, а тест `der_maps_swapped_labels`
явно закрепляет такое поведение. Это правильно для анонимной диаризации,
но перестановка двух настоящих профилей может дать идеальный DER.

Правила: [P10] проверка пользовательского сценария, [P12] обезличенные тестовые данные.

Исправление: сохранить DER и добавить независимую проверку идентичности без
перестановки имён. На открытых голосовых примерах использовать искусственные
профили A/B и незнакомый голос C; на частных записях эталоны и пакеты держать
только локально. Проверять ложные назначения, долю речи с верным профилем,
долю неизвестных и число спикеров отдельно.

## Что показывают локальные артефакты

У одной стереозаписи длительностью 735,4 с есть два завершённых запуска
с одинаковыми записанными опциями распознавания:

| Путь обработки | Именованных спикеров | Итоговых реплик |
|---|---:|---:|
| Раздельные каналы | 6 | 108 |
| Сведение в моно | 8 | 98 |

На 495,4 с, где оба документа содержат ровно одного говорящего, назначенные
имена различаются на 51,7 с, то есть на 10,4% этого сравнимого времени.
Это расхождение результатов, а не измеренная ошибка: эталон отсутствует.
Один запуск выполнен с изменённым рабочим деревом, снимка голосовых пакетов
нет; поэтому это свидетельство для воспроизведения, а не контролируемый A/B.
Аудио, тексты, имена, пути и векторы в PR не включаются.

## Обязательные сценарии приёмки

| Сценарий | Проверяемое поведение |
|---|---|
| Моно, 2 известных голоса и 1 неизвестный | Известные профили не меняются местами, неизвестному не выдаётся чужое имя |
| Стерео, наушники, локальная и системная речь | В документе и при обучении сохранены исходные каналы 0/1 |
| Стерео, колонки, эхо и одновременная речь | Тихая локальная речь сохраняется; эхо не создаёт самостоятельный именованный голос |
| Цифровой дубль, выбран исходный правый канал | Образец и извлечение читают правый канал, а не перенумерованный левый |
| Реплика 5 с, чистого аудио 0,8 с | Полная длина не позволяет пройти двухсекундный допуск к имени |
| Перекрывающиеся окна и короткий ответ другого участника | Чистое время не удваивается, ответ не поглощается соседним говорящим |
| Настоящее моно и неоднозначный источник в стерео | Моно с `channel=None` работает; неоднозначное стерео не обучает профиль на первом канале молча |

На детерминированных сценариях A/B/C — ноль ложных имён и ноль перестановок
исходных каналов. На замороженном локальном наборе — меньше неверно
именованного времени, чем у `131ba7d`, без ухудшения относительно выбранной
базовой версии; долю неизвестных и потери речи показать отдельно.
Число карточек и хороший cosine сами по себе не являются критерием успеха.
Если возврат раздельного пути возвращает текстовые дубли, это нужно исправить
в существующем эхогейте/дедупликации и повторить приёмку до выхода из draft.

Личные пакеты не удалять и не пересчитывать автоматически. Если отдельно
подтвердится загрязнение прототипов, подготовить локальный список сомнительных
образцов с возможностью прослушивания и ручного исправления.

## Реализация

Автоматический `fold_playback` удалён. Исходные индексы сохраняются после выбора
цифрового дубля и передаются репликам и образцам. Обучение отклоняет неоднозначный
или недопустимый канал до изменения профиля. Чистое время считается как покрытие
окон без перекрытий PyAnnote; допуск к имени действует во всех режимах. Кластеры
без допуска не наследуют профиль через согласование каналов.

Добавлены проверки исходного правого канала, неоднозначного источника, уникального
чистого времени и перестановки профилей при нулевом DER. Локальный набор поддерживает
`identity_turns` для проверки имён без перестановки. Пользовательские пакеты не меняются.

Проверена расшифровка 90 с реального стерео на изолированной копии пакетов:
процесс завершился успешно, получено 20 реплик с исходными каналами 0/1.
Это проверка работоспособности, а не измерение точности имён. Добавлен отдельный
тест запрета транзитивного присвоения имени через промежуточный кластер.

Проверка всех cargo features обнаружила существующую ошибку компиляции GPU-пути
ORT: builder должен быть изменяемым для `commit_from_file`. Исправлена локально
без изменения списка провайдеров. Документация собирается с прежними предупреждениями
rustdoc в `mr-ml`; новый код не добавляет публичных элементов.

## Проверка отдельных реплик после слияний

Выявлен дополнительный путь ошибки: имя корректно сопоставленного центроида
распространялось на чужую реплику внутри того же кластера. Значение сходства
объединённой карточки не являлось оценкой этой реплики.

После всех слияний добавлена независимая проверка исходного аудио именованных
реплик от 1,5 с чистого голоса. Используется тот же ERes2NetV2 и тот же matcher:
без новых моделей и изменения глобальных порогов. Перекрытия PyAnnote исключаются. Акустическое эхо проверяется как голос
его источника, чтобы микрофонный дубль не сохранял чужое имя. При противоречии
другое имя назначается только при прохождении общего matcher; неоднозначная
реплика получает анонимную метку. Короткие фрагменты и ошибки инференса не
вызывают принудительной смены говорящего. Образцы и векторы карточек строятся
заново по проверенным репликам после повторной дедупликации каналов.

Синтетические проверки покрывают противоречие общему кластеру, близкие оценки,
отсутствующий профиль и неоднозначную альтернативу. Живой тест на открытых
WAV-примерах проверяет исправление метки, исходного канала, образца и карточки
с сохранением текста и временных границ. Полные частные записи проверяются
на изолированных копиях голосовых пакетов; содержимое в репозиторий не входит.

Проверены три локальных примера: противоречивая реплика 3,9 с получает анонимную
метку, а реплики 1,7 с и 9,2 с подтверждают соответствующие профили. На этих
контрольных интервалах ошибочные исходные имена после финальной проверки не
сохраняются. Первый случай остаётся неоднозначным по общему matcher, поэтому
правильное имя не назначается принудительно. Результат относится к выбранным
интервалам; полная точность диаризации записей этим не измерена.
