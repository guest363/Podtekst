# Эталон дикторов в синтетических встречах

## Почему исходный выбор клипов недостаточен

Первоначальный генератор выбирал разные файлы FLEURS и назначал каждому отдельную метку спикера. Разные файлы не гарантируют разных дикторов: метаданные не содержат глобального speaker ID. Поле `id` в исходном TSV обозначает предложение. В локальном RU-наборе для 185 таких ID встречаются оба значения gender, а текст внутри каждого ID одинаков; считать это поле идентификатором человека нельзя.

Числовая проверка исходной RU-пары выявила повод проверить эталон. Эмбеддинги полных клипов имеют cosine **0,8668**. Для непересекающихся фрагментов длиной 1,5 с получены:

| Сравнение | Число пар | Cosine min | Median | Max |
|---|---:|---:|---:|---:|
| Разные части источника 0 | 6 | 0,5042 | 0,6464 | 0,7076 |
| Разные части источника 1 | 6 | 0,4600 | 0,5633 | 0,6941 |
| Между источниками 0 и 1 | 16 | 0,2902 | 0,5378 | 0,7099 |

Сходство между источниками сопоставимо со сходством разных частей одного источника. Это **не устанавливает личность или тождество дикторов** и не является правилом построения нового эталона. Оно показывает, почему предположение «клип = уникальный диктор» нельзя принимать без независимого основания.

## Основание нового отбора

[Официальная статья FLEURS](https://simran-khanuja.github.io/assets/fleurs_slt.pdf) описывает сбор трёх записей **каждого предложения разными носителями языка**. Гарантия относится к записям одного предложения, а не к произвольным разным клипам. Две записи одного sentence ID в неполном наборе сохраняют это основание различимости.

Новый отбор использует только sentence ID, различающиеся записи и gender из исходного TSV. Порядок детерминирован: числовой sentence ID, затем имя файла; модель и cosine в отборе не участвуют. Для объединения разных sentence-групп используется противоположный gender. Этот дополнительный аргумент опирается на корректность и согласованность gender-метаданных; сам по себе gender не является уникальным speaker ID.

| Локальный test-набор | Sentence-группы | Однополые тройки | Однополые группы с ≥2 записями | Выбранная четвёрка |
|---|---:|---:|---:|---|
| RU | 344 | 34 | 114 | Три MALE одного предложения + одна FEMALE другого |
| EN | 350 | 0 | 166 | Две FEMALE одного предложения + две MALE другого |

В RU-тройках 18 групп MALE и 16 FEMALE. В EN есть 297 пар и 53 одиночные записи; однополых пар 122 FEMALE и 44 MALE. Для RU-сценариев с двумя и тремя дикторами используются соответствующие префиксы выбранной тройки. Для EN-сценария с двумя дикторами используются две записи одного предложения.

Все восемь выбранных WAV найдены в уже локальных архивах, без сетевой загрузки: моно, 16 кГц, float32. Число отсчётов проверено по TSV и заголовкам аудио. Длительности RU: 17,16 / 18,84 / 17,58 / 12,78 с; EN: 10,68 / 11,52 / 8,38 / 11,16 с.

## Артефакты и сравнение результатов

Относительно локального корня бенчмарка:

- Исходные метаданные: `tmp/hf/fleurs/data/<lang>/test.tsv`; аудио: `tmp/hf/fleurs/data/<lang>/audio/test.tar.gz`.
- Подготовка: отслеживаемый `tools/diar_eval/prepare_fleurs_speakers.py`.
- Каноническое доказательство отбора для CI: `diar-regression-clips/proof.json`; оно содержит sentence ID, gender, число отсчётов и SHA-256 извлечённых WAV. Первичный исследовательский снимок сохранён отдельно в `runs/level-fix/fleurs-distinct/proof.json`.
- Выбранные файлы имеют только числовые имена внутри языкового каталога. Аудио, тексты и исходные имена файлов не включаются в этот документ или репозиторий.

Для воспроизведения нужны этот скрипт и те же локальные TSV/архивы. Следует повторить metadata-only отбор, проверить совпадение SHA-256 с `proof.json`, затем отдельно построить встречи и RTTM. Сам Markdown без этих артефактов не является автономным бенчмарком.

Исходные встречи и их результаты сохраняются для истории. Их SCA — точность воспроизведения **меток клипов**, а DER — ошибка относительно RTTM с этими метками; интерпретировать эти числа как точность различения реальных людей нельзя. В частности, число обнаруженных голосов меньше числа клипов само по себе не доказывает ошибку диаризации.

Для встреч с подтверждённым по метаданным отбором формируется **отдельный baseline**. Числа прежнего и нового наборов не подменяют друг друга. Изменение эталона не доказывает исправность алгоритма и не оправдывает настройку порогов по cosine этих источников. Пороги диаризации и сопоставления профилей этим аудитом не меняются.
