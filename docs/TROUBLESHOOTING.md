# Если что-то не работает

Сначала соберите отчёт диагностики: «Настройки» → «Компоненты» →
«Собрать отчёт». Приложение сохранит zip с версией, платформой, разрешениями,
устройствами, состоянием моделей и последними строками лога. Аудио, расшифровок
и голосовых отпечатков в нём нет, домашний каталог заменён на `~`, имена
устройств скрыты.

Из терминала то же самое делает `podtekst --diagnostics`: команда печатает путь
к архиву. Лог лежит в папке данных приложения, подпапка `logs/app.log`;
путь к папке данных виден в отчёте.

Перед отправкой откройте `logs/app.log` и уберите всё личное: фрагменты текста
могут попасть в сообщения об ошибках.

## macOS: «невозможно открыть»

Релизы сознательно не подписаны Apple Developer ID и не нотаризованы,
поэтому Gatekeeper блокирует скачанный `.dmg`. Проверьте SHA-256 по
`SHA256SUMS` из релиза и один раз снимите карантин:

```bash
xattr -dr com.apple.quarantine /Applications/Podtekst.app
open /Applications/Podtekst.app
```

Или: правый клик по приложению → «Открыть» → «Открыть».
Подробнее: [UNSIGNED-INSTALL.md](UNSIGNED-INSTALL.md).

## macOS: нет микрофона или собеседников

Разрешения выдаются в «Системные настройки» → «Конфиденциальность
и безопасность»:

- «Микрофон» - для вашего голоса;
- «Запись экрана и системного аудио» - для собеседников и записи экрана.

После выдачи доступа перезапустите приложение. Пока разрешения нет, в интерфейсе
висит предупреждение «Системный звук: нужно разрешение», а запись идёт только
с микрофона.

Если разрешение включено, а предупреждение остаётся, проверьте, что оно выдано
именно запущенной копии приложения. После обновления неподписанной сборки старая
запись разрешения может перестать действовать: удалите Подтекст из списка
кнопкой «−», запустите приложение и выдайте доступ заново.

Системный звук берётся через ScreenCaptureKit, BlackHole не нужен. Если
ScreenCaptureKit недоступен, установите BlackHole 2ch и выберите его источником
системного звука в настройках.

## 2 канала, но спикеры путаются

Режим «Встреча · 2 канала» рассчитан на наушники. Если звук встречи идёт из
колонок, микрофон записывает и ваш голос, и собеседников, поэтому оба канала
несут почти одну и ту же речь. Приложение замечает это перед расшифровкой и
оставляет только микрофонный канал: в отчёте будет пометка «общий микс
(каналы дублируют речь)». Это не ошибка — так убираются двойные реплики,
но речь, слышная только в системном канале, может не попасть в текст.
Чтобы сохранить разделение, наденьте наушники и повторите запись.

## В записи тихие собеседники

1. Проверьте индикатор «Собеседники» во время звонка: он должен двигаться.
2. Убедитесь, что выбран режим «Встреча · 2 канала» и вы в наушниках.
3. На Bluetooth-наушниках звук может уходить в режим гарнитуры. Переключите
   наушники на другое устройство и обратно, запись должна продолжиться.
4. Если в логе есть `sys_silent`, системный канал пуст: проверьте разрешение
   и устройство вывода.

## Нет записи экрана

Запись экрана требует ffmpeg с кодировщиком H.264. Откройте «Настройки» →
«Компоненты» → у ffmpeg нажмите «Скачать». Переключатель записи экрана
включится без перезапуска.

На macOS дополнительно нужно разрешение «Запись экрана и системного аудио».

## Модель не скачалась

- Проверьте свободное место: базовый набор занимает около 300 МБ, Whisper -
  около 1 ГБ.
- Неполный файл лежит рядом с расширением `.part`; повторное скачивание
  продолжит с места обрыва.
- После скачивания проверяется SHA-256. При несовпадении файл удаляется
  и скачивается заново.

## Не работает обновление

Обновление ставится только из установленной сборки (AppImage / `.app` /
NSIS). Пакет проверяется minisign-подписью ключом проекта; если подпись не
сходится, приложение откажется его ставить. Это не связано с подписью
Apple/Microsoft.

Если кнопка «Обновить и перезапустить» выдаёт ошибку, скачайте пакет со
страницы релизов вручную, проверьте SHA-256 и установите поверх. Перед
установкой закройте приложение.

На macOS обновление ставится только для `.app` из `/Applications`; запуск
из исходников через `run.sh` обновляется через `git pull`.

## Windows: SmartScreen и Smart App Control

Установщик не подписан Authenticode. В окне предупреждения: «Подробнее» →
«Выполнить в любом случае». Если включён Smart App Control, неподписанное
приложение может быть заблокировано без кнопки обхода. Не отключайте
SmartScreen, Smart App Control или Defender глобально: используйте машину
без Smart App Control либо соберите приложение из исходников.

SHA-256 и подробности: [UNSIGNED-INSTALL.md](UNSIGNED-INSTALL.md).

## Куда писать

Откройте issue по шаблону «Bug report» и приложите отчёт диагностики.
Не прикладывайте аудио, расшифровки, `voiceprints.json` и `people.json`.
Уязвимости - по инструкции в `SECURITY.md`, не в публичный issue.
