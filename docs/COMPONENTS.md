# Компоненты

Модели и ffmpeg закреплены за сборкой Подтекста. Приложение не проверяет версии
в фоне и не запрашивает их из сети. Оно показывает то, что записано в его
манифесте, и устанавливает компонент по кнопке. За новыми версиями в исходных
репозиториях (апстримах) следят CI и локальный скрипт проверки.

Состав сборки задают два файла:

* `src-tauri/crates/mr-models/models-manifest.json` - модели: файлы, ревизии
  апстримов, размеры, SHA-256, порядковый номер (`order`);
* `src-tauri/crates/mr-app/components-pins.json` - ffmpeg: версия, источник,
  архив и SHA-256 для каждой платформы.

Пин - это запись о версии компонента, его файлах и контрольных суммах, если они
есть. Пользователь получает ровно то, что проверили при выпуске.

## Как проверяются компоненты

1. **Монитор.** `./scripts/components.sh monitor` сверяет ревизии из манифеста и
   пины ffmpeg с апстримом и печатает отчёт: что изменилось и где новая версия.
   В CI он запускается раз в неделю. При расхождении монитор открывает одну
   задачу в GitHub (issue) с меткой `dependencies`, при совпадении закрывает её.
   Ошибки сети не считаются совпадением: в отчёте остаётся пометка о неполной
   проверке. Файлы монитор не меняет.
2. **Валидация.** `./scripts/components.sh lint` проверяет структуру без сети:
   обязательные поля, формат SHA-256, имена файлов, ссылки на ревизию вместо
   `main`, полный набор пинов ffmpeg. `./scripts/components.sh verify-ffmpeg`
   скачивает архив по пину текущей платформы, сверяет SHA-256, версию,
   архитектуру и кодировщики.
3. **Пины.** Новую версию вписывают в файлы сборки вручную: ревизию апстрима,
   контрольные суммы, размеры и `order` больше прежнего. Для ffmpeg в
   `components-pins.json` указывают версию, URL архива и SHA-256.
4. **Релиз.** `./scripts/components.sh report` объединяет линт, монитор и
   проверку ffmpeg в `runs/components/<дата>-<коммит>/report.md`. Отчёт
   прикладывают к PR выпуска. Линт входит в CI-гейт. В заметках к релизу
   обязательна строка «Компоненты:» с версиями моделей и ffmpeg, вошедшими в
   сборку.

## Политика обновлений

* **Модели приходят с обновлением приложения.** Новый манифест входит в
  сборку. Файлы не скачиваются без команды: пользователь нажимает «Обновить»,
  а старая копия заменяется только после проверки размера и SHA-256 нового
  набора.
* **ffmpeg устанавливается и обновляется по кнопке.** «Скачать», если утилиты
  нет, «Обновить», если версия или архитектура расходятся с пином,
  «Переустановить», если файлы на месте, но не запускаются или версии ffmpeg и
  ffprobe не совпадают. Копия приложения лежит в папке данных и имеет приоритет
  над системной.
* **Системный ffmpeg приложение не меняет.** Если пользователь установил
  утилиту сам, приложение работает с ней и показывает источник «системный».
  Обновляет её пакетный менеджер.
* **Версии не смешиваются.** Поддерживается одна версия компонента на сборку:
  манифест и пины меняются вместе, старые наборы не предлагаются к установке.
* **Уведомлений о релизах апстрима нет.** Приложение не узнаёт о новых версиях
  и не показывает баннеров. Расхождение с апстримом находит монитор.

## Ограничения

* **Linux:** статическая сборка johnvansickle выкладывается без SHA-256, поэтому
  контрольная сумма архива не закреплена: проверяются размер, состав (только
  `ffmpeg` и `ffprobe`, без абсолютных путей, `..` и символических ссылок),
  архитектура и версия. Версия сверяется с пином строго: когда johnvansickle
  выпускает новый релиз, установка останавливается с ошибкой «апстрим
  обновился», пока пин не обновят в `components-pins.json`.
* **macOS:** поддерживается только arm64. Сборка для Intel не выпускается, и
  пин для неё не задан.
* **Android:** ffmpeg не используется. Запись экрана и импорт видео доступны
  только на десктопе.
* **Windows:** архив gyan.dev содержит оба бинарника; версия и архитектура
  проверяются по заголовку PE до установки.
