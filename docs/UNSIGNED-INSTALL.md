# Установка неподписанных сборок

Подтекст не подписывает релизы сертификатами Apple Developer ID и Windows
Authenticode. Это сознательная политика проекта: платные сертификаты не
окупаются, а код остаётся открытым. Поэтому macOS и Windows показывают
предупреждения при первом запуске.

При этом целостность пакетов проверяется двумя независимыми способами:

* `SHA256SUMS` в каждом релизе - контрольные суммы всех файлов, включая
  `latest.json`;
* `latest.json` и файлы `*.sig` - minisign-подписи ключом проекта. Встроенный
  апдейтер ставит только пакет, подпись которого сходится с публичным ключом
  в приложении.

Скачивайте пакеты только со страницы
[Releases](https://github.com/guest363/podtekst/releases).

## Проверка SHA-256

Скачайте пакет и `SHA256SUMS` в одну папку.

Linux и macOS:

```bash
sha256sum -c SHA256SUMS --ignore-missing
```

На macOS вместо `sha256sum` есть `shasum`:

```bash
grep '\.dmg$' SHA256SUMS | shasum -a 256 -c -
```

Windows PowerShell:

```powershell
$file = (Get-ChildItem "Podtekst_*-setup.exe" | Select-Object -First 1).Name
$actual = (Get-FileHash $file -Algorithm SHA256).Hash.ToLower()
$expected = (Select-String -Path SHA256SUMS -Pattern ([regex]::Escape($file))).Line.Split()[0]
if ($actual -ne $expected) { throw "SHA-256 не совпал" }
"SHA-256 совпал: $actual"
```

Если хэш не совпал, не запускайте файл: скачайте его заново.

## macOS

1. Проверьте SHA-256 `.dmg` по `SHA256SUMS`.
2. Откройте `.dmg` и перетащите `Podtekst.app` в `/Applications`.
3. Снимите карантин с установленной копии:

   ```bash
   xattr -dr com.apple.quarantine /Applications/Podtekst.app
   open /Applications/Podtekst.app
   ```

4. Либо без терминала: правый клик по `Podtekst.app` → **«Открыть»** →
   **«Открыть»** в диалоге. Подтверждение нужно один раз.

Если macOS пишет, что приложение «повреждено», это не признак вируса:
так система реагирует на отсутствие подписи и карантин. Проверьте SHA-256,
убедитесь, что файл скачан с официального релиза, и повторите шаг 3.

Gatekeeper и notarization не отключаются глобально: приложение просто не
подписано, а защиту системы менять не нужно.

## Windows

1. Проверьте SHA-256 установщика по `SHA256SUMS`.
2. Запустите `.exe`. SmartScreen покажет «Windows защитила ваш компьютер».
   Нажмите **«Подробнее»** → **«Выполнить в любом случае»**.
3. Если включён Smart App Control, неподписанное приложение может быть
   заблокировано без кнопки обхода. Не отключайте Smart App Control или
   Defender глобально ради установки. В этом случае используйте другую машину
   без Smart App Control либо соберите приложение из исходников по
   [README](../README.md).

Не добавляйте установщик в исключения Defender и не отключайте защиту
Windows целиком: это ослабляет систему сильнее, чем предупреждение о
неподписанном файле.

## Linux

`.AppImage` не требует установки. Проверьте SHA-256, выдайте файлу право на
запуск (`chmod +x`) и запустите. Если в системе нет FUSE, используйте
`--appimage-extract-and-run`.

## Обновления

Автообновление не зависит от подписи операционной системы. Приложение
скачивает `latest.json`, берёт пакет для своей платформы и проверяет
minisign-подпись публичным ключом, вшитым в сборку. Пакет с неверной подписью,
чужим ключом или подписью для другой версии не устанавливается.

Если обновление не ставится, скачайте новый пакет вручную, проверьте SHA-256
и установите поверх старой версии. Данные и записи останутся на месте.
